걷기는 접지 → 무릎을 굽혀 체중 받기 → 반대 다리 통과 → 지지 발의 뒤꿈치를 들고 발끝 밀기 순서다. 후반 4장은 반대 발이 지지하며 팔도 반대로 움직인다. 모든 프레임에 지지하는 발 또는 발끝이 바닥에 닿는다. 3/7번의 과도한 무릎 들기를 낮춰, 앞으로 내미는 신발이 지면 가까이를 지나게 했다. 머리 기준점과 몸 크기를 통일하고 상하 움직임은 약 3px로 제한했다.

머리는 몸 전체를 정규화할 때 함께 확대·축소하지 않는다. `image_gen`으로 만든 깨끗한 머리·목·옷깃을 `walk-head.png`에 56×56 픽셀로 저장했다. 내보내기는 기존 머리를 어깨·옷깃 경계까지 제거한 뒤 이 공통 레이어를 크기 변경 없이 합성한다. 일반·휴대폰 OFF·플래시 ON의 24개 자세가 모두 같은 머리 픽셀을 쓰며, 움직임은 상하 3px 이내의 평행 이동뿐이다. 머리 뒤 회색 잔상과 기존 턱·목 조각도 제거한다. 앞으로 내민 휴대폰과 LED는 보존한다. `docs/previews/suho-walk-head-consistency.gif`에서 3종의 머리를 같은 높이로 맞춰 전후 비교할 수 있다.

휴대폰은 먼쪽 손으로 잡고, 빈손인 가까운 팔은 어깨·팔꿈치·손목이 보이도록 그렸다. 빈손은 다리와 반대로 흔들린다. 0/1/7번에서는 뒤쪽, 2/6번에서는 중간, 3/4/5번에서는 앞쪽을 지난다. 모든 자세는 휴대폰을 잡은 팔 하나와 빈손 팔 하나로 구성한다. ON은 생성된 LED 부분만 OFF에 정렬해 합성했으므로, 플래시를 전환해도 몸과 팔이 바뀌지 않는다.

2026-10-20 사용자 요청으로 **플래시를 켠 채 달릴 수 있다**. 새 `jeong-suho-phone-run-sixteen-on.png`는 `phone-movement-source/run-sixteen-on-generated.png`를 `scripts/prepare-flashlight-run.mjs`로 패킹한 16프레임 시트다. 기존 걷기·일반 달리기 재생성 절차와 별도로 관리한다. `jeong-suho-phone-jump-on.png`는 기존 보존 시트 `jeong-suho-phone-run-on.png`의 2/6번 공중 자세만 픽셀 그대로 추출한 점프·낙하 전용 2프레임 시트다. 지상 달리기에는 사용하지 않는다.

달리기는 원래 전신 8동작을 보존하고, 일반 달리기의 0·1번 사이에 [새 전신 중간 동작 한 장](../RUN-MID-01-PROMPT.md)을 추가했다. 머리·몸통·팔·골반·다리를 잘라 붙이지 않고, 몸이 연결된 전신 그림만 사용한다. 런타임 16개 타이밍 셀에는 원래 자세를 두 번씩 넣되 일반 달리기의 타이밍 1번만 새 중간 자세로 교체한다. 일반 달리기는 9개, 휴대폰 달리기는 8개 고유 자세이며 기존 선택·재생 간격·휴대폰·점프 처리를 유지한다. 몸통 비율이 다른 중간 시안과 어색한 분리 합성은 사용하지 않는다. 제외된 시안의 기록은 [RUN-UPPER-BODY-PROMPTS.md](RUN-UPPER-BODY-PROMPTS.md)에 있다.

앞발의 중복된 뒤꿈치/밑창은 [신발 수정 원본](../RUN-SHOE-FIX-PROMPT.md)으로 교체한다. 일반 원본 0·3·7번과 휴대폰 0번의 x150–249/y196–255 영역만 수정하며, 정강이 중심과 기존 발바닥 높이에 맞춰 연결한다. 그 밖의 상체·뒤쪽 발·중간 동작은 그대로 보존한다. 원래 제작 시트는 보관하고, 실제 게임용 16셀 시트 내보내기에 항상 이 수정을 적용한다. 검증은 수정 영역 밖 픽셀 보존, 하나로 연결된 앞쪽 신발, 발목 연결을 검사하며 기존 0번의 중복 신발은 같은 검사에서 실패하는지 확인한다.

현재는 [걷기·달리기 전체 하체 수정](../MOVEMENT-LEGS-FIX-PROMPTS.md)도 함께 적용한다. 일반 걷기 3·4·7번, 휴대폰 OFF/ON 걷기 3·7번, 일반 달리기 원본 1·3·6번, 휴대폰 달리기 원본 1·2·5번에서 겹친 종아리·신발을 교체한다. 수정된 하체는 골반 중심과 기존 바닥 높이에 맞추며, y128 위의 그림은 전혀 바꾸지 않는다. 손과 셔츠 끝을 보호해 하체를 바꿀 때 팔이 잘리거나 새 손이 덧그려지지 않도록 한다. 기존 앞발 수정과 겹치는 프레임은 이 하체 수정 결과가 최종 적용된다. 앞뒤 신발을 모두 검사해 56개 걷기/달리기 타이밍 셀 각각에 큰 신발 실루엣이 2개인지 확인한다.

런타임 셀은 256×256, 걷기는 한 주기 184px 이동(200px/s에서 0.92초), 달리기는 288px 이동(340px/s에서 약 0.847초)이다. 달리기 이동 속도는 유지하면서 애니메이션 반복만 이전 0.565초보다 느리게 조정했다. [수정 전후 GIF](../../../docs/previews/suho-run-upper-body-stability.gif)는 왼쪽이 잘못된 상체 합성, 오른쪽이 복구된 전신 동작이며 같은 속도로 재생한다.

프로젝트 루트의 `node scripts/prepare-movement-inbetweens.mjs`가 최근접 보간·알파 정리·몸 정렬·공통 머리 합성·셀 배열을 수행해 시트를 재생성한다. 몸의 정렬 기준은 원본 머리 중심 x=135, 발 기준선은 일반 239/휴대폰 237이다. 공통 머리는 x=106, 기준 y=17(휴대폰 15)에 위치한다. ON/OFF는 OFF의 정렬값을 공유한다. 광원 좌표는 `js/scene/camera.js`의 실제 LED 위치에 맞췄다.

검증은 `tests/movement-inbetweens.mjs`와 `tests/phone-movement.mjs`다. 걷기 24개 자세의 머리·턱·목·옷깃 픽셀 일치, 머리 주변과 목뒤의 투명 영역, 기존 턱 조각의 부재를 검사한다. 달리기는 기존 전신 픽셀 보존, 새 중간 동작 한 장만 적용되는지, 머리 크기·위치와 중간 착지 위치를 검사한다. 일반 9개·휴대폰 8개 고유 자세, 기존 점프 픽셀, 프레임 선택·재생 주기·이동 속도와 휴대폰 처리를 확인한다. 기존 `suho-run-inbetweens.gif`는 중간 프레임 시안의 기록이다.
