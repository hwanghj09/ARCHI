# 1층 로비 배경 합성 기록

## 3차(최종, 2026-09-26) — 스타일·크기 보정 프롬프트로 다시 받은 그림

17층 원본 프롬프트 문장을 기준으로 다시 쓴 프롬프트(`PROMPT.md`)로 받은 그림을 적용했다. 이전 두 번의 시도와
달리 색감(차가운 블루-시안)과 문 크기는 이번에 잘 나왔지만, **바닥선이 native y=474**였다(720 기준 79.2%가
아니라 65.8%쯤 — 이 그림만 별도로 배율이 필요했다). 처리 순서:

1. 바닥선 배율 570/474=1.2025로 가로·세로 동일하게 확대(6013×866 → 720으로 크롭). 이 배율 하나만 적용하고
   그 외에는 리샘플하지 않았다 — 배율을 재는 것은 항상 픽셀 밝기 스캔으로 하고 어림잡지 않는다(1층에서
   두 번째 겪은 실수).
2. 확대하니 폭이 6013px로, 목표 5000px보다 1013px 남았다. **문·소품이 전혀 없는 두 군데 빈 벽**만 원본
   그대로 잘라내 폭을 맞췄다(늘리거나 채운 곳은 한 군데도 없다 — 17층/12층 문 수정과 같은 원칙):
   - 비상계단 문(x=3500..3610) 끝과 화장실 타일 시작(x=3700 부근) 사이 빈 콘크리트 벽에서 650px 제거
     (x=3660..4310 구간).
   - 안내판(건물 게시판, 잘라내기 전 기준 x=5325..5525) 뒤쪽 빈 벽에서 나머지 363px 제거(1차 제거 이후
     좌표로 x=4875..5238 구간).
   - 두 이음매 모두 마침 벽 패널·기둥 경계와 겹쳐서 확대해봐도 이어붙인 티가 거의 안 난다(스크린샷
     `f1-seam1.png`/`f1-seam2.png` 참고 — 둘 다 벽 재질이 바뀌는 자리라 자연스럽다).
3. 문 5개(엘리베이터 3대·비상계단·화장실) 위치를 **잘라낸 뒤의 최종 그림 기준으로 다시** 격자+정밀 스캔해
   실측했다(1·2차 그림과는 완전히 다른 값이다 — 매번 새로 재야 한다):
   - 엘베1 x=2280..2465(폭185), 엘베2 x=2665..2860(폭195), 엘베3 x=2975..3195(폭220),
     비상계단 x=3500..3610(폭110), 화장실 문 x=3855..3990(폭135).
   - `BUILDING_CORE` 기준값과 비교해 `elevatorOffsetX`(카별 배열)/`elevatorWidthDelta`(카별 배열)/
     `stairsOffsetX`/`stairsWidthDelta`/`restroomOverride`로 이 층 전용 보정만 넣었다(그림도 공용 좌표도
     안 건드림). 계산식: `widthDelta = 실측폭 - 기본폭`, `offsetX = 실측중심 - 기본중심`(중심 좌표로 풀어야
     두 값이 서로 얽힌 공식에서 정확히 나온다 — `player.js`의 엘리베이터/계단 위치 계산부 주석 참고).
   - Playwright로 `f1`의 `.door`/`.room-door` 엘리먼트 `style.left`/`width`를 직접 찍어 위 실측값과 정확히
     일치하는지 확인했고, 그 좌표로 그림 위에 초록 박스를 그려 문마다 딱 맞는 것도 눈으로 확인했다.
4. 로비 소품(안내 데스크·화분 3개·대기 소파·정수기)도 이 최종 그림 속 실제 가구 위치에 맞춰 다시 옮겼다
   (안내 데스크 x=925, 나머지는 문 사이 빈 벽 구간에 적당히 분산). 안내 데스크 옆 "경비 로봇"은 이번
   그림에도 그려지지 않아서(에셋도 없음) 인터랙션 메시지로만 낸다 — 15층 인사팀 화이트보드 단서와
   이어지는 문구.

**다시 그림을 바꿀 때 체크리스트**:
1. 바닥선 native 행을 픽셀 스캔으로 재라(어림잡지 마라 — 이 그림처럼 79.2% 규칙을 안 따를 수 있다).
2. 배율 적용 후 폭이 5000보다 크면, 문·소품이 없는 빈 벽 구간을 찾아 그만큼만 원본 그대로 잘라내 맞춘다
   (타일링·채우기 없이). 작으면 반대로 빈 벽 구간에서 반복 타일링으로 채운다(7층 lab.png 사례 참고).
3. 문 5개 위치를 최종(잘라내기 끝난) 그림 기준으로 다시 격자/스캔해서 재고, 카별 배열 값을 새로 계산해
   넣는다. 이전 시도의 좌표를 재사용하지 않는다 — 그림이 바뀔 때마다 완전히 달라진다.
4. Playwright로 실제 DOM 좌표를 찍어 실측값과 일치하는지 반드시 확인한다.

## 1·2차 시도(폐기)

- 1차: 4구역 분할 프롬프트로 받은 그림(문 폭이 60~75px씩 좁고 장식 기둥이 넓게 나옴) — 크기 문제로 폐기.
- 2차: 자체 서술형 스타일 지시로 받은 그림(바닥이 물기 있는 대리석처럼 반짝이고 창밖이 사진처럼 디테일해
  다른 층과 톤이 안 맞음, 실측 결과 가장 밝은 하이라이트가 RGB 121,114,104로 따뜻한 톤 — 12층은
  137,143,140) — 색감 문제로 폐기. 이 두 실패에서 배운 것을 `PROMPT.md`의 COLOR GRADE/SCALE REFERENCE
  절에 반영해 3차에서 해결했다.
