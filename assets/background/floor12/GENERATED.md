# 12층 배경 그림과 실제 적용 규격 (2026-09-28 재작성)

## 현재 마감 (2026-10-16)

- 실내는 원본 y=100..569 픽셀을 그대로 유지한다. 위 100px은 공용 천장 패널·환기구·꺼진 조명, 아래 y=570..760은 공용 바닥으로 채워 화면 위아래의 단색 빈 띠와 아래층 배관 단면을 없앤다. 창·블라인드·평가 모니터·문·이동한 출구의 좌표는 유지한다.
- 복도는 `walls-layout.json`과 공용 벽 모듈로 합성한다. 개발실은 혼합 유리, 모델 평가실은 불투명 벽, 팀장실은 간유리다. 공용 벽 부분은 이웃 층의 밝기·채도에 맞추고, 원본 문 그림은 아래 범위를 그대로 얹는다.

- `build.py`는 실내 벽 픽셀 유지와 완전 불투명 채움을 자체 검사한다. `tests/elevator.mjs`의 12층 경로는 마감본 크기·이름표·단서·보조키·방 출입을 검사하고, `tests/room-spatial-layout.mjs`와 `tests/floor12-restroom.mjs`가 출구 그림·비상구 표시등·가구 간격 및 PC·터치 왕복을 검사한다.

## 바닥선 검출

원본은 "문/벽이 끝나고 어두운 단면이 시작되는" 경계에 밝은 가로줄(보행 바닥선)이 있다. 이미지 높이의
60~92% 구간에서 **행 평균 밝기가 가장 높은 행**을 찾는 방식으로 7장 전부 자동 검출한 뒤, 빨간 선을 그은
복사본을 만들어 육안으로 문/바닥 경계와 정확히 겹치는지 확인했다(전부 일치). 검출값(원본 픽셀 기준):

## 합성 방법

`scripts/compose-floor12-art.py`가 조각마다 다음을 한다:
1. `s = 목표 월드 폭 / 원본 폭` (가로세로 동일 배율 — 왜곡 없음, 위 표의 비율이 거의 정확히 맞아서 가능했다)
2. `top = 570 - floor_y × s`
3. 캔버스(목표 배경색으로 채움)에 `(x_offset, round(top))` 위치로 그대로 붙인다. `top`이 양수면 그 위 빈 띠는
   장면 배경색이 채우고, 스케일된 이미지 아래쪽이 720을 넘으면(바닥선 아래 단면 부분) 캔버스 밖으로 잘린다 —
   둘 다 설계 의도대로다(`PROMPT.md`의 "게임 연결 계획" 3번).

```
python scripts/compose-floor12-art.py <corridor-1> <corridor-2> <corridor-3> <dev-1> <dev-2> <eval> <lead>
```

## 연결 (`js/floors/floor-12.js`)

```js
FLOOR12_LAYOUT.backgroundImage = { src: 'assets/background/floor12/corridor.png', height: 720, top: 0 };
// f12-dev  → { src: 'assets/background/floor12/office.png', height: 720, top: 0 }
// f12-eval → { src: 'assets/background/floor12/eval.png',   height: 720, top: 0 }
// f12-lead → { src: 'assets/background/floor12/lead.png',   height: 720, top: 0 }
```

네 이미지 모두 자연 픽셀 크기가 이미 해당 장면의 `config.width`(복도 5000 / 개발실 3280 / 평가실 1804 /
팀장실 2132)와 정확히 같은 720 높이 PNG라서 `width`는 지정하지 않았다(기본값 `config.width`를 그대로 씀,
`scene-builder.js`의 `art.width ?? config.width`). `backgroundWallsOnly`는 쓰지 않았다 — 이 그림들은 door 17층
`assets/objects/`처럼 문까지 이미 그려져 있는 "완성 배경"이라, `data-art="true"`(기본 art 모드)가 적용되어야
`.floor-room`/`.room-door`의 CSS 벽·문이 자동으로 숨는다(엘리베이터 3대·비상계단은 항상 그렇듯 `assets/objects/
floor17/`의 DOM 오버레이가 그 위를 덮는다).

`index.html`의 art 모드 CSS도 함께 손봤다: 기존 `[data-art="true"]` 규칙은 `.floor-room::before`와 `.room-door`
본체만 지워서, `.floor-room.lab::after`(성능평가실 앞면의 노란-검정 경고띠)와 `.room-door.slide::before`
(개발실 자동문 위 센서), `.room-door.security::after`(성능평가실 카드리더) 같은 개별 가상요소는 그림 위에
그대로 겹쳐 보이는 문제가 있었다. `.floor-room::after`와 `.room-door::before`/`.room-door::after`를 함께
지우도록 일반화했다 — 12층뿐 아니라 앞으로 art 모드를 쓰는 다른 층에도 같이 적용된다.

## 아직 안 한 것 / 확인할 점

- 문 좌표(`doorX`/`doorWidth`/`doorY`) 미세 보정은 하지 않았다. 그림 속 문이 판정 박스와 몇 px 이상
  어긋나 보이면(특히 성능평가실 doorX=3160/화장실 doorX=3612/팀장실 doorX=4700 부근) 실측 후 `FLOOR12_LAYOUT`
  값을 그림에 맞춰 조정한다. 각 방 내부의 출구(`exitX`는 지정하지 않음 — `exitDoorX()`가 복도 문 위치 비율로
  자동 계산)도 마찬가지로 그림과 비교해 어긋나면 방 안 소품(`props`)의 `x`를 조정하거나 문서에 `exitX`를
  추가한다.
- 이 층은 아직 자동 검증 테스트(`checkFloor12` 같은 것)가 없다. 16층(`tests/floor16-art.mjs`)을 본떠 이미지
  로드, `data-art`, 바닥선 정렬(각 조각 x 지점에서 밝기 스캔해 570과 비교)을 검사하는 테스트를 추가할 수 있다.
- 폴더에 남아 있는 고아 파일(`art-corridor-*.png`, `art-interior-*.png`, `dev.png`, `lab.png`, `lounge.png`)은
  지금 코드가 참조하지 않는다. 삭제 여부는 사용자에게 확인 후 진행한다.

## 안팎 공간 정합 보정 (2026-10-11)

방 경계는 실제 복도 그림의 유리벽·기둥을 따른다. 모델 평가실 문이 설정된 방 밖에 있던 문제와
팀장실·화장실 전면이 겹치던 문제를 바로잡았다. 코어 설비와 복도 문 그림 위치는 유지한다.

| 방 | 복도 전면 x / 폭 | 내부 출구 x |
| --- | --- | --- |
| 개발실 | 48 / 1070 | 2202 |
| 모델 평가실 | 2960 / 543 | 270 |
| 팀장실 | 4070 / 723 | 1475 |

`exitArt`로 원본 배경의 문·문틀·표시등을 옮겨 복도 문 양옆 공간 비율과 맞춘다. 원래 문 자리는 같은 원본의
벽 조각으로 채우며 PNG 크기와 단서는 유지한다. 새 문 뒤에서 잘릴 대형 화면은 벽 조각으로 비우고,
가까운 책상·화이트보드·랙은 출입 공간에서 옮겼다. 상호작용 테두리도 문과 함께 이동한다.

화장실 전면은 실제 타일 벽 `3592..3993`이다. 내부에 왼쪽 벽 581px를 더해 출구 x766, 내부 폭2381로
맞추고 배경·설비·조사 영역을 함께 이동한다. 원래 1800px 배경은 늘리지 않아 거울과 세면대 간격이 유지된다.
`tests/room-spatial-layout.mjs`와 화장실 테스트가 실제 문 비율, 그림·테두리 정렬, 가구 간섭과 PC·터치 왕복을 검사한다.
