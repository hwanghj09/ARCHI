# 경비 로봇 검증 — 2026-10-04

기존 테스트 7개와 추가 회귀 테스트 11개 그룹을 실행했다. 벽 끝에서 붙잡힌 플레이어가 충돌 경계 밖으로 이동하는 버그 1건을 수정했다. 수정 후 순찰·붙잡기 테스트를 재실행했고, 추가 회귀 테스트는 Playwright Chromium, 설치된 Chrome, Edge에서 검증했다.

## 발견 및 수정

로봇이 왼쪽 끝 x=80에서 바로 옆의 수호를 붙잡으면 수호를 x=-2로 배치했다. 오른쪽에서도 같은 문제가 있었다. 붙잡기 시작 시 32px 벽과 플레이어 몸체의 반폭을 고려해 붙잡을 위치를 제한하고, 로봇 위치를 함께 조정했다. 팔과 수호 사이의 82px 간격은 유지된다. 양쪽 벽 재현 테스트와 화면 확인으로 검증했다.

추가 회귀 테스트 그룹:

1. 좌우 감지 방향 × 거리 8개 × 높이 4개, 총 64개 경계값.
2. 추적 속도 270px/s, 수호가 반대편으로 이동할 때 방향 전환, 스캔 중 감지, 추적 해제 후 재감지.
3. 양쪽 벽 끝에서 붙잡힌 몸체의 충돌 경계 및 팔 간격.
4. 휴대폰을 열어도 추적이 계속되고, 붙잡히면 휴대폰이 닫히며 재시도 화면으로 전환되는지 확인. 키패드·전력 패널을 열었을 때는 추적 정지, 닫은 뒤 정상 재개.
5. 팔 전개·붙잡기 7개 시점에서 전원 차단 시 해제, 복구 후 재감지.
6. 추적·팔 전개·붙잡기 중 장면 교체 시 입력 잠금·로봇·도크 정리 및 복귀.
7. 정비 암호 오입력·정답 입력, 단서 보존, 마우스·Space 재시도 5회.
8. 붙잡힐 때 휴대폰·라이트·누른 이동 입력 해제, 재시도 후 자동 이동 방지.
9. 568×320 모바일 가로 화면에서 재시도 버튼의 화면 내 배치 및 터치.
10. 고정 시간 간격으로 시뮬레이션한 10분 동안 순찰 범위 1510~4540 유지, 반복 회전, 로봇 중복 없음.
11. 브라우저 스크립트 오류 및 실패한 리소스 요청 없음.

1280×720 데스크톱, 390×844 모바일 세로, 568×320 모바일 가로 화면을 검사했다. 수정 후 양쪽 벽과 붙잡기 화면도 직접 확인했다.

## 재실행

```powershell
rtk proxy node tests/guard-patrol.mjs
rtk proxy node tests/guard-capture.mjs
rtk proxy node tests/guard-regression.mjs
$env:GUARD_BROWSER = 'chrome'
rtk proxy node tests/guard-regression.mjs
$env:GUARD_BROWSER = 'msedge'
rtk proxy node tests/guard-regression.mjs
Remove-Item Env:GUARD_BROWSER
```

캡처는 `.local/guard-*.png`에 저장한다. Chrome과 Edge는 해당 브라우저가 설치되어 있어야 한다.

## 범위의 한계

Windows의 headless 브라우저에서 실행했다. 모바일은 화면 크기와 터치 입력 에뮬레이션이며 실기기 검증은 아니다. Safari/Firefox, 실제 GPU의 프레임률과 장시간 메모리 사용량은 측정하지 않았다. 10분 순찰은 게임 시간 시뮬레이션이다. 검증한 시나리오는 모두 통과했지만 모든 가능한 입력 조합의 무결함을 보장하는 것은 아니다.
