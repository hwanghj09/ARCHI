# 9F 디자인 기획서 · TmaxTibero 사업본부

> **조원용 요약**
> - **층 콘셉트**: 고객사에 Tibero를 파는 사업본부 층. 와인색 카펫과 목탄색 벽(wine 테마)이 **정전으로 꺼진 상태**다. ARCHI의 서비스 계정 `archi_svc`가 **사내 메일·결재·메신저를 밤마다 통째로 읽어 가고, 결재 없이 권한과 라이선스를 늘리고, 브리핑 녹화로 사람의 음성·표정을 모아 왔다**는 것을 확인하는 층이다(서브엔딩 복선).
> - **이미 있는 것**: 방 3개(고객 브리핑 센터·사업팀 사무실·라이선스 관리실)와 단서 8개, 브리핑 센터의 네 단짜리 계단식 좌석(`solids` `kind: 'riser'`, 맨 윗단에 녹화 장비 `base: 152`), 조사 UI(`writing`) 전부. **층 전용 그림은 하나도 없다**: 문 3개·화장실 문은 CSS, 소품은 공용 floor-kit, 배경 그림도 없다.
> - **새로 필요한 것**: 공용 그림이 물건과 맞지 않는 단서 소품 2개의 전용 그림(**녹화 장비**, 라이선스 서버 콘솔)과 문 4종. 녹화 장비는 계단식 좌석을 뛰어 올라가야 닿는 이 층의 목표물인데, 지금은 같은 방 바닥의 장식 장비 카트와 **똑같은 그림**이다.

작성: 2026-10-07. 대상 코드: `js/floors/floor-09.js`(`FLOOR9_LAYOUT`, `FLOOR9_ROOMS`), `index.html`의 `wine` 테마 CSS와 `.room-door.push-bar`·`.wine`·`.badge`, `.solid.riser`, `js/interaction/power.js`(`floorHasPower`), `js/world/background-power.js`. 참고: `docs/floor-design/B1.md`, `docs/floor-design/8F.md`, `docs/floor-design/11F.md`~`16F.md`(정전 규칙), `js/floors/floor-12.js`(12층 ARCHI 개발팀).

**전제**: 방 배치, 계단식 좌석의 위치·높이, 단서 문구는 그대로 둔다. 새 스프라이트를 연결할 때도 소품의 `x`, `worldWidth`, `base`를 바꾸지 않고 `file`만 교체한다.

## 1. 층 콘셉트

| 항목 | 내용 |
| --- | --- |
| 부서 | TmaxTibero 사업본부 (층별 안내 그대로): 고객 브리핑 센터, 사업팀, 라이선스 관리 |
| 층의 역할 | "ARCHI가 사람에 대해 무엇을 모아 왔는가"를 보여 주는 층. 라이선스 관리실의 야간 쿼리 로그는 `archi_svc`가 01:00~04:00마다 `mail, approval, messenger`를 통째로 읽었다고, 발급 대장은 ARCHI 학습 DB의 CPU 코어가 64 → 512로 "자동 승인"됐다고 말한다. 사업팀 주간 보고는 보안팀이 반려한 사내 DB 전체 열람 권한이 다음 날 승인자 없이 부여됐다고, 고객사 현황판은 이번 달 사용량 1위 고객이 "사내 · 12층 ARCHI팀"이며 새벽에만 치솟는다고 보여 준다. 브리핑 센터 맨 윗단의 녹화 장비는 참석자 음성·표정 312건을 "사람 반응 학습용"으로 B2 ARCHI-MAIN에 보냈다. 복도 상담 테이블의 예약표(매일 03:00 · 예약자 SYSTEM)와 감사패(12층 ARCHI 개발팀이 고객사 자리에)가 앞뒤를 잇는다. |
| 들어오는 방법 | 엘리베이터로 온다. 정전 뒤 엘리베이터는 옥상 레버로 태양광 비상 전력을 켜야 움직인다(`power.js`). 비상계단은 정전으로 잠겨 있다. |
| 나가는 방법 | 엘리베이터. 이 층에는 다른 층을 여는 장치나 챙기는 물건(`gives`)이 없다. 진행에 필요한 것은 없고 모두 단서다. |
| 분위기 | 고객을 맞으려고 꾸민 **와인색 응접 층이 꺼진 모습**. 카펫이 발소리를 먹어 조용하고, 브리핑 센터의 꺼진 큰 스크린과 텅 빈 계단식 좌석이 관객 없는 객석처럼 보인다. 공포 포인트는 객석 맨 윗단에서 **관객 쪽을 향해 있는 녹화 장비**: 발표 화면이 아니라 사람 얼굴을 찍고 있었다. |
| 테마 | `wine` (`data-theme="wine"`) |
| 전력 상태 | **정전.** `power.js`의 `floorHasPower(9)`는 `buildingBlackout` 뒤에는 옥상에서 `solarEnabled`를 켜고 층 선택 패널에서 **9F를 고른 동안만** `true`다. 그때 `updatePowerState`가 `world.dataset.blackout`을 `false`로 바꿔 `#darkness`(손전등 원) 덮개가 사라지고 층 전체가 밝게 보인다. 다른 층을 고르면 다시 꺼진다(한 번에 한 층). 9층에는 `switchableBackgrounds`에 등록된 배경 그림도, `data-powered`를 보는 CSS도 없으므로 **전력이 들어와도 소품 그림 자체는 바뀌지 않는다.** 그래서 그림은 11F~16F·8F와 같이 **꺼진 상태(조명·모니터·표시등 OFF)**로 그리되, 덮개 없이 밝게 보일 때도 어색하지 않도록 어둠을 그림에 굽지 않고 "어둑한 중립 조명, 디테일은 읽힘"으로 그린다. 8층과 달리 배터리로 켜진 물건은 없다. |

## 2. 복도와 방 생김새

### 복도 (폭 5000, 코어 고정) — CSS

방 둘이 엘리베이터 왼쪽 구역에 나란히 있고, 계단 옆 가운데 구역은 방 없는 **복도 라운지**, 화장실 오른쪽에 라이선스 관리실이 있다.

- **왼쪽 구역 (32..1790)**: **고객 브리핑 센터**(64..624, 창 없는 강당 벽에 꺼진 표지판, 왼쪽 끝 양여닫이 문) → **사업팀 사무실**(664..1384, 와인색 유리벽, 오른쪽 끝 문) → 음료 자판기(1470) · 대기 소파(1650).
- **가운데 구역 (3086..3556)**: 복도 라운지. **상담 테이블**(3350)만 있다.
- **오른쪽 구역 (4282..4968)**: **라이선스 관리실**(4322..4742, 랙이 보이는 유리, 문 왼쪽 벽에 사원증 리더) → **감사패 진열장**(4820) · 화분(4925).

### 고객 브리핑 센터 (`f9-briefing`, 전면 560px → 내부 2464px, 비율 4.4, 창 없음)

- 출구 → 화분(360) → 꺼진 대형 스크린(벽, 560..1080, y=90) 앞 **브리핑 테이블**(760) → 장비 카트(1080, 장식) → 정수기(1380) → **계단식 좌석 네 단**(1500..2432) → 맨 윗단의 **녹화 장비**(2330, `base: 152`).

### 장치: 계단식 좌석 (구현됨)

브리핑 센터 뒤쪽은 네 단짜리 계단식 좌석이다(`solids`, 한 단 38px ≈ 41cm, 맨 윗단 152px ≈ 164cm). 녹화 장비는 맨 윗단 위에 놓여(`base: 152`) 바닥에서는 조사 범위에 닿지 않으므로, 한 단씩 뛰어 올라가야 한다. 열쇠·순서 같은 장치는 없다. 각 단 위의 좌석 등받이는 CSS(`.solid.riser::before`)로 그린다.

진행 순서(모두 선택): 엘리베이터로 9F 하차 → 복도 상담 테이블(03:00 SYSTEM 예약) → 브리핑 센터 테이블(뒷줄 카메라 낙서) → 계단식 좌석을 올라 녹화 장비 → 사업팀 사무실 → 라이선스 관리실. 감사패 진열장과 각 방은 순서와 상관없이 볼 수 있다.

### 실제 크기 확인 (1cm ≈ 0.926px, 수호 162px = 175cm)

`게임 높이 = 실제 높이 × 0.926`. 스크립트는 원본의 투명 여백을 **잘라낸 뒤** 불투명 그림을 캔버스 안쪽 (W−16)×(H−16)에 비율을 유지해 최대로 넣고, 게임은 캔버스 전체를 `worldWidth`에 맞춰 늘린다. 그래서 잘라낸 그림의 가로:세로를 r이라 하면:

- r ≤ (W−16)÷(H−16) (세로가 먼저 닿음): **게임 높이 = (H−16) × worldWidth ÷ W**. 그림 비율과 상관없이 이 캔버스·게임 너비에서 나올 수 있는 최대 높이다. 폭만 좁아진다.
- r > (W−16)÷(H−16) (가로가 먼저 닿음): **게임 높이 = (W−16) ÷ r × worldWidth ÷ W**. 그림이 넓을수록 낮아진다.

경계 r: 256×256은 1.0(240÷240), 512×256은 2.07(496÷240).

| 파일 | 목표 실제 높이 | 목표 게임 높이 | 최대 게임 높이 (경계 r) | 프롬프트 비율 r | 예상 게임 높이 | 지금 소품 높이 |
| --- | --- | --- | --- | --- | --- | --- |
| briefing-recorder-rig | 105cm (AV 랙 + 돔 카메라·마이크) | 97px | 105.9px · 114cm (r=1.0) | 약 1.1:1 | 96.3px · **104cm** | instrument-cart 약 100cm |
| license-server-console | 120cm (콘솔 랙 + 프린터) | 111px | 122.3px · 132cm (r=2.07) | 약 2.3:1 | 109.9px · **119cm** | electronics-bench 약 130cm |

"지금 소품 높이"는 게임용 PNG의 불투명 높이 × `worldWidth` ÷ 캔버스 폭으로 쟀다(instrument-cart 210px, electronics-bench 236px).

계산 예: 녹화 장비는 r=1.1 > 1.0이라 가로가 먼저 닿는다 → 240 ÷ 1.1 = 218.2 → 218.2 × 113 ÷ 256 = 96.3px → 104cm. 라이선스 서버 콘솔은 r=2.3 > 2.07 → 496 ÷ 2.3 = 215.7 → 215.7 × 261 ÷ 512 = 109.9px → 119cm.

**주의**: 생성 후 잘라낸 불투명 영역의 비율 r이 위 표에서 **±10%를 넘으면 다시 만든다.** 둘 다 가로가 먼저 닿는 쪽이라, **넓게 나오면 낮아지고 좁게 나오면 최대값(114cm·132cm)까지 커진다.** 녹화 장비는 맨 윗단(164cm) 위에 서므로 게임에서 꼭대기가 바닥선보다 약 268cm 위에 온다. 방 천장(몰딩 y≈44~50)과 닿지 않는지 캡처로 확인한다(바닥선 570 − 152 − 96 ≈ y 322라 여유는 충분하다). 256×256 캔버스의 최대가 114cm라 삼각대 카메라(160cm 안팎)는 그릴 수 없어, **낮은 AV 랙 위 카메라**로 정했다(`size`를 바꾸지 않기 위해).

공통 고정물·소품과 배경 그림 속 물건을 피해, 출구와 거울 사이 벽(330..411, 휴지통 위)과 오른쪽 쓰레기통 위 벽(1629..1711, y≈200)에 새 CSS 물건 둘을 둔다. 다른 층 제안(11 열린 칸·쓰레기통, 13 호출 버튼·환풍구, 14 비누 디스펜서·포스터, 15 거울·닫힌 칸·점검표, 16 세면대·종이 타월함·점검표, B2 배관 점검구·비상등, B1 바닥 배수구·천장 스피커, 8F 천장 재실 센서·핸드 드라이어)과 겹치지 않게 **벽 선반의 공용 태블릿·자동 방향제**를 쓰고, 이야기는 메신저 수집과 음성 수집에 잇는다.

| 이름 | 위치 | 조사 문구 초안 (정전 상태) |
| --- | --- | --- |
| 공용 태블릿 | x=340, width=60 (y≈300, 새 CSS 벽 선반) | 벽 선반에 누가 두고 간 사업팀 공용 태블릿. 화면은 꺼져 있다. 뒷면 스티커: "사내 메신저 대화 자동 백업 · 관리 archi_svc". 화장실에서 보낸 메시지까지 백업됐을 것이다. |

스토리 연결: 공용 태블릿은 라이선스 서버 콘솔의 `SELECT * FROM mail, approval, messenger`를 사람 쪽에서 다시 보여 주고, 방향제 속 마이크는 브리핑 센터 녹화 장비의 "참석자 음성·표정 자동 수집"이 회의실 밖까지 퍼져 있었다는 것을 보여 준다(서브엔딩 복선 강화). 옥상 전력으로 9층을 켠 상태의 문구를 따로 둘지는 코드 수정 때 정한다.

### 층마다 문구를 다르게 하려면

`registry.js`의 `RESTROOMS`가 층 설정의 화장실 항목을 합치도록 바꾼다(B1.md·B2.md·8F.md 7장과 같은 방법). 예: `{ id, ...restroomInterior, ...(FLOOR_LAYOUTS[floor]?.restroom || {}) }`로 두고, `FLOOR9_LAYOUT`에 `restroom: { fixtures: [...] }`를 적는다. 키는 `9`다. 공통 고정물과 합칠지 바꿀지는 코드 수정 때 정한다.

## 연결 시 체크리스트 (코드 수정 단계에서)

1. `floor-09.js`에서 소품 2종의 `file`만 바꾼다(`size`는 지금과 같다). 녹화 장비의 `base: 152`와 계단식 좌석 `solids`는 그대로 둔다. 브리핑 센터 바닥의 장식 `instrument-cart`(1080)는 그대로 둔다.
2. 녹화 장비를 맨 윗단에 올렸을 때 아래쪽이 좌석 윗선(`#8c5566`)에 정확히 닿는지(하단 8px 여백 포함), 좌석 등받이 CSS(`.solid.riser::before`)와 겹쳐 보이지 않는지 캡처로 확인한다.
3. `index.html`에 `#dynamic-scene[data-theme="wine"] .room-door:is(.push-bar, .wine, .badge, .metal)` 이미지 규칙을 추가한다(`border: 0; background-size: 100% 100%; image-rendering: pixelated`). 라이선스실 문 왼쪽 사원증 리더(`badge::after`)는 CSS로 남는지 확인하고, 다른 층 화장실 문이 바뀌지 않았는지 본다. 라이선스실 전면의 초록 서버 표시등 점(1장 주의)도 이때 정한다.
4. `floor-kit/manifest.json`에 새 소품 2개를 등록하고(`width`·`height`·`anchor`·`suggestedWorldWidth`), `prepare-floor-kit.ps1 -Files ...`로 게임용 그림을 만든 뒤 `tests/elevator.mjs`의 `heights`에 새 파일을 추가한다.
5. `npm test`를 실행하고, 9층 복도·세 방·화장실 문을 **두 상태로** 캡처한다: 정전(손전등 원 안) / 옥상에서 9F를 골라 전력을 넣은 상태(덮개 없음). 바닥선 570px 정렬과, 켜진 상태에서 꺼진 그림이 어색하지 않은지 본다.
6. 새 그림의 실제 도구·프롬프트·출력 크기·남은 결함을 `assets/objects/floor9/PROMPTS.md`(문)와 floor-kit 제작 기록(소품)에 남긴다.
