# B2 디자인 기획서 · 서버실

> **조원용 요약**
> - **층 콘셉트**: ARCHI 메인 서버실이 있는 마지막 층. 건물 전체가 정전인데도 **비상 발전기로 불이 켜져 있는 유일한 층(B1과 함께)**이고, 푸른 서버 불빛과 붉은 경고색(core 테마) 속에서 기획.md의 일곱 가지 진실을 한 번에 확인한다. 엔딩(ARCHI 삭제 진행 + 최종 추격)이 벌어질 곳이다.
> - **이미 있는 것**: 방 3개(메인 서버실·전력·냉각실·연결 실험실)와 단서 9개, 복도 감시 카메라 1대(`cameras`)와 사각 기둥, 조사 UI(`writing`) 전부. **층 전용 그림은 하나도 없다**: 문 3개·화장실 문은 CSS, 소품은 공용 floor-kit(서버 랙·작업대·배전반·UPS 등), 배경 그림도 없다.
> - **새로 필요한 것**: 단서가 걸린 공용 소품 6개의 전용 그림(**ARCHI 메인 콘솔**, CCTV 분배함, 수전 전환반, 냉각 설비 일지, 신경 신호 변환기, 실험 기록 카트), CSS로 그린 인간-시스템 연결 장비 1개, 문 4종(메인 서버실 문은 잠김 2상태). 경비 로봇 셋은 1층 R-01 그림을 다시 쓴다. 삭제 진행·최종 추격은 코드가 아직 없어 제안만 한다.

작성: 2026-10-04. 대상 코드: `js/floors/floor-b2.js`(`B2_LAYOUT`, `B2_ROOMS`), `index.html`의 `core` 테마 CSS, `js/interaction/cctv.js`. 참고: `기획.md`의 "B2 - 사건의 진실", "최종 추격 및 엔딩", `assets/objects/guard-robot/PATROL-PROMPT.md`.

**전제**: 방 배치, 단서 문구, 감시 카메라(`cameras`)·CCTV 분배함(`gives: 'b2-cctv-off'`)·B1의 운행 제한 해제는 그대로 둔다. 새 스프라이트를 연결할 때도 소품의 `x`와 `worldWidth`를 바꾸지 않고 `file`만 교체한다.

### 장치: 감시 카메라와 잠기는 서버실 문 (구현됨)

카메라가 비추는 구간에 들어가면 ARCHI가 메인 서버실 문을 잠그고(`(잠김)`), 시야에서 벗어나 5초가 지나야 풀린다. 카메라가 문 쪽을 볼 때 복도를 건너 기둥 밑(1120..1240)에 숨었다가, 엘리베이터 쪽으로 돌아가는 순간 문으로 들어간다. 안에서 CCTV 분배함 전원선을 뽑으면 카메라가 꺼지고 이후엔 자유롭게 드나든다.

진행 순서: B1에서 운행 제한 해제 → B2 하차 → 카메라 타이밍 맞춰 메인 서버실 진입 → 분배함으로 카메라 끄기 → 메인 콘솔에서 진실 확인. 전력·냉각실과 연결 실험실은 순서와 상관없이 볼 수 있다.

### 엔딩 흐름 (기획.md 기준, 코드 없음 · 제안)

지금 코드는 콘솔 문구에서 끝난다(`floor-b2.js` 머리말 "삭제 퍼즐과 추격은 아직 없다"). 지금 배치를 그대로 쓰면 이렇게 이어진다.

1. **시작**: 메인 콘솔(1400)에서 `DELETE ARCHI` 실행. 기획.md는 마지막 삭제 퍼즐을 "휴대폰 메모를 조합하는 방식"으로 두었다(관리자 확인 칸).
2. **진행 표시**: 천장 외부 전송 현황 화면(1900..2400)이 `ARCHI DELETE PROCESS 0% → 100%`로 바뀐다. 지금 이 화면은 CSS라 진행률을 코드로 바꾸기 쉽다(6장에서 그림으로 바꾸지 않는 이유).
3. **경보**: B2 비상등이 붉게 바뀌고, 복도 오른쪽 끝(4760..4940)의 경비 로봇 셋이 깨어나 붉은 LED로 바뀐다. 로봇은 **화장실·엘리베이터·비상계단을 지나 왼쪽 끝 서버실까지** 와야 하므로, 복도 전체가 추격 무대가 된다.
4. **버티기**: 삭제가 진행될수록 ARCHI의 통제가 무너진다. 초반 카메라·문·조명·로봇 정상 → 중반 카메라와 문 오작동 → 후반 조명 꺼짐, 로봇 움직임·통신 불안정. 끈 카메라(`b2-cctv-off`)가 초반에 다시 켜지는 연출도 가능하다.
5. **결말**: 100%까지 버티면 `TRUE END - ARCHI OFFLINE`(로봇 정지, 비상등 꺼짐). 그 전에 잡히면 `SUB END - NEW HOST`: 연결 실험실의 연결 장비·신경 신호 변환기·"대체 호스트: 정수호" 기록이 그대로 복선이 된다.

1층 R-01의 붙잡기·다시 시도(`js/scene/guard-patrol.js`)를 로봇 셋으로 넓히는 것이 가장 가까운 구현 경로다.

## 7. 화장실 상호작용

### 현재 구조

- 모든 층의 화장실 내부는 **17층 화장실 하나를 같이 쓴다.** `js/floors/helpers.js`의 `restroomInterior`(폭 1800, 창 없음, 배경 `assets/background/floor17/restroom.png`)를 `js/floors/registry.js`의 `RESTROOMS`가 층마다 `{ id: 'b2-restroom', ...restroomInterior }`로 복사한다.
- 모든 층에 공통으로 세면대 거울(520), 화장실 칸(820), 비상 호출 버튼(1450) 고정물과 위생용품 수납장(90), 휴지통(380), 미끄럼 주의 표지(1130) 소품이 있다.
- B2는 전력이 켜진 층이라 **불 켜진 화장실 그림**(`restroom.png`)이 맞다. 지상층처럼 소등판(`restroom-off.png`)으로 바꾸지 않는지 연결 때 확인한다.
- 배경 그림에 그려진 것 (월드 좌표): 긴 거울 x≈413..912, 세면대 3개 x≈445..876, 종이 타월함 x≈944..1012, 열린 칸 x≈1071..1280, 닫힌 칸 문 x≈1362..1552, 오른쪽 쓰레기통 x≈1629..1711. 출구 x≈185..330(E 힌트 157..358).

### B2 화장실 조사 요소 제안

공통 고정물·소품과 겹치지 않는 빈 자리(1200..1420, 1560..1760)에 새 CSS 물건 둘을 둔다. 다른 층 제안(11 열린 칸·쓰레기통, 13 호출 버튼·환풍구, 14 비누 디스펜서·포스터, 15 거울·닫힌 칸·점검표, 16 세면대·종이 타월함·점검표)과 겹치지 않게 **배관 점검구·비상등**을 쓰고, 이야기는 전력·냉각실의 UPS와 잇는다.

| 이름 | 위치 | 조사 문구 초안 (전력 켜진 상태) |
| --- | --- | --- |
| 배관 점검구 | x=1250, width=100 (새 CSS 철판, 벽 아래) | 벽 아래 점검구 덮개가 미지근하다. 안쪽에서 냉각수가 쉬지 않고 흐르는 소리가 난다. 위층은 전부 정전인데, 이 층의 펌프만 돌고 있다. |
| 천장 비상등 | x=1650, width=60 (y≈60, 새 CSS 등) | 비상등이 하얗게 켜져 있다. 옆 작은 표시: "비상 발전기 회선 · 보호 대상 변경 예정". 전력·냉각실 UPS에서 비상 조명이 "보호 안 함"으로 바뀌어 있던 것이 떠오른다. |

스토리 연결: 비상등은 UPS의 "비상 조명 · 보호 안 함"과 이어져, 엔딩에서 조명이 꺼지는 단계(기획.md "후반: 조명이 꺼지고")를 미리 알려 준다. 배관 점검구는 냉각 설비 일지의 "새벽마다 냉각 부하 최대"를 몸으로 느끼게 한다.

### 층마다 문구를 다르게 하려면

`registry.js`의 `RESTROOMS`가 층 설정의 화장실 항목을 합치도록 바꾼다. 예: `{ id, ...restroomInterior, ...(FLOOR_LAYOUTS[floor]?.restroom || {}) }`로 두고, `B2_LAYOUT`에 `restroom: { fixtures: [...] }`를 적는다. 키는 `[-2]`다. 공통 고정물과 합칠지 바꿀지는 코드 수정 때 정한다.

## 연결 시 체크리스트 (코드 수정 단계에서)

1. `floor-b2.js`에서 소품 6개의 `file`만 바꾼다(`size`는 지금과 같다). CCTV 분배함의 `gives`·`message`·`takenMessage`와 카메라 설정은 그대로 둔다.
2. 인간-시스템 연결 장비는 지금 CSS 고정물이라, 같은 자리(800..1060)에 `link-chair-rig` 소품을 두고 고정물은 투명한 조사 상자로 남기거나, 고정물에 스프라이트를 그리는 방식을 고른다. 조사 문구·`writing`은 그대로 옮긴다.
3. `index.html`의 core 테마에 `#dynamic-scene[data-theme="core"] .room-door:is(.core-glass, .coolant-door, .linklab-door, .metal)` 이미지 규칙을 추가한다(`border: 0; background-size: 100% 100%; image-rendering: pixelated`). 메인 서버실 문은 `background-size: 200% 100%`로 두고 잠김(`[aria-label$="잠김"]`)일 때 오른쪽 칸을 보인다(16층 CU 셔터 방식). 다른 층 화장실 문이 바뀌지 않았는지 확인한다.
4. 경비 로봇 셋을 R-01 시트로 바꾸면 `dormant-bots` CSS 그림은 끈다. 엔딩 추격을 만들 때 `guard-patrol.js`를 여러 대로 넓힌다.
5. `floor-kit/manifest.json`에 새 소품을 등록하고, `tests/elevator.mjs`의 `heights`에 새 파일을 추가한다.
6. `npm test`를 실행하고, B2 복도·세 방·화장실 문을 캡처해 바닥선 570px 정렬과 밝기(필터 없이 켜진 그림)를 확인한다. 카메라 잠김 때 문 그림이 빨간 칸으로 바뀌는지도 본다.
7. 새 그림의 실제 도구·프롬프트·출력 크기·남은 결함을 `assets/objects/b2/PROMPTS.md`(문)와 floor-kit 제작 기록(소품)에 남긴다.
