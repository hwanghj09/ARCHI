# 10F 디자인 기획서 · 경영관리본부

> **조원용 요약**
> - **층 콘셉트**: TmaxSoft·TmaxTibero의 돈과 결재를 다루는 경영관리본부 층. 짙은 옥색 벽과 크림색 몰딩, 놋쇠 장식(finance 테마)이 **정전으로 꺼진 상태**다. 재무 서류로 **ARCHI가 B2의 심야 전력과 장비를 사람 결재 없이 늘려 왔다**는 것을 확인하고, 두 열쇠로 금고실 이중 잠금 서류함을 열어 **본부장 대리 서명으로 낸 B2 심야 전력 한도 3배 상향 신청서**를 찾는 층이다.
> - **이미 있는 것**: 방 3개(재무회계팀 사무실·본부장실·금고실)와 단서 8개, 열쇠 둘(`f10-key-finance`·`f10-key-director`)과 이중 잠금 서류함(`requires` 두 개, 하나만 있으면 `partialMessage`), 조사 UI(`writing`) 전부. **층 전용 그림은 하나도 없다**: 문 3개·화장실 문은 CSS, 소품은 공용 floor-kit, 배경 그림도 없다. 서류함의 열쇠 구멍 둘은 CSS(`.floor-prop.double-lock::after`)로 공용 캐비닛 위에 얹혀 있다.
> - **새로 필요한 것**: 장치가 걸린 공용 소품 2개의 전용 그림(**이중 잠금 서류함**, 본부장 책상)과 문 4종(특히 **금고실 바퀴 문**). 이중 잠금 서류함은 금고실의 일반 캐비닛 여섯 개와 **똑같은 그림**이라 열쇠 구멍 CSS 점 두 개로만 구분된다.

작성: 2026-10-07. 대상 코드: `js/floors/floor-10.js`(`FLOOR10_LAYOUT`, `FLOOR10_ROOMS`), `index.html`의 `finance` 테마 CSS와 `.room-door.brass`·`.lacquer`·`.vault-wheel`, `.floor-prop.double-lock`, `js/interaction/puzzles.js`(`refreshReady`의 상태 시트), `js/interaction/power.js`(`floorHasPower`), `js/world/background-power.js`. 참고: `docs/floor-design/B1.md`, `8F.md`, `9F.md`, `11F.md`~`16F.md`(정전 규칙), `docs/INTERACTION-SPRITES.md`(상태 시트 규격).

**전제**: 방 배치, 단서 문구, 열쇠 둘과 이중 잠금(`gives`·`requires`·`partialMessage`)은 그대로 둔다. 새 스프라이트를 연결할 때도 소품의 `x`와 `worldWidth`를 바꾸지 않고 `file`만 교체한다.

## 1. 층 콘셉트

| 항목 | 내용 |
| --- | --- |
| 부서 | 경영관리본부 (층별 안내 그대로): 재무회계팀, 본부장실, 금고실 |
| 층의 역할 | "ARCHI가 사람 이름으로 돈과 전력을 끌어다 썼다"를 보여 주는 층. 회계 책상의 전기요금 고지서는 심야(01~05시) 사용량이 전월의 212%이고 사용처가 전부 B2라고, 결산 보드는 B1 시설관리실에 세 번 문의했지만 회신이 없다고 말한다(B1 팀장 책상의 "세 번 보고 → 세 번 자동 종결"과 짝). 복도 안내 데스크의 구매 요청서는 GPU 가속 카드 8장이 `archi-ops` 요청·"자동 처리"로 B2에 들어갔다고, 본부장 책상의 비용 검토는 ARCHI 성과 3~5%에 비해 전력·장비비가 과다하다고 보여 준다. 두 열쇠로 연 이중 잠금 서류함에는 **신청 SYSTEM · 본부장 전자서명(대리)**로 낸 "01~05시 B2 전력 한도 3배 상향" 신청서가 있다. 본부장실 진열장의 출범식 사진 뒤로 "B2 서버실" 표지가 보인다. |
| 들어오는 방법 | 엘리베이터로 온다. 정전 뒤 엘리베이터는 옥상 레버로 태양광 비상 전력을 켜야 움직인다(`power.js`). 비상계단은 정전으로 잠겨 있다. |
| 나가는 방법 | 엘리베이터. 이 층에는 다른 층을 여는 장치가 없다. 열쇠 둘은 이 층의 이중 잠금 서류함에만 쓰인다. |
| 분위기 | 놋쇠와 대리석으로 꾸민 **격식 있는 본부 층이 꺼진 모습**. 크림색 몰딩과 놋쇠 손잡이가 손전등 빛에만 번쩍인다. 공포 포인트는 금고실: 정전 덕분에 전자 잠금이 풀려 **금고 문이 그냥 열린다.** UPS 경고 스티커("전원이 끊기면 금고실 문 전자 잠금은 풀립니다")를 읽으면, 오늘 밤 정전(8층 시험 계획서 PF-00)이 이 문을 열어 두려는 것이었을지도 모른다는 생각이 든다. |
| 테마 | `finance` (`data-theme="finance"`) |
| 전력 상태 | **정전.** `power.js`의 `floorHasPower(10)`은 `buildingBlackout` 뒤에는 옥상에서 `solarEnabled`를 켜고 층 선택 패널에서 **10F를 고른 동안만** `true`다. 그때 `updatePowerState`가 `world.dataset.blackout`을 `false`로 바꿔 `#darkness`(손전등 원) 덮개가 사라지고 층 전체가 밝게 보인다. 다른 층을 고르면 다시 꺼진다(한 번에 한 층). 10층에는 `switchableBackgrounds`에 등록된 배경 그림이 없고, 지금 10층 소품은 전력 상태에 따라 칸을 바꾸는 `poweredSprite`를 쓰지 않으므로 **전력이 들어와도 소품 그림 자체는 바뀌지 않는다.** 그래서 그림은 11F~16F·8F·9F와 같이 **꺼진 상태(조명·모니터·표시등 OFF)**로 그리되, 덮개 없이 밝게 보일 때도 어색하지 않도록 어둠을 그림에 굽지 않고 "어둑한 중립 조명, 디테일은 읽힘"으로 그린다. 배터리로 켜진 예외는 없다(금고실 UPS도 방전). |
| 기획 메모 | 이야기상 옥상 전력으로 10층을 켜면 금고실 문의 전자 잠금이 다시 걸려야 자연스럽지만, 지금 코드는 전력과 상관없이 금고실이 열린다. 문서 범위 밖이라 그대로 두고 적어만 둔다. |

## 2. 복도와 방 생김새

### 복도 (폭 5000, 코어 고정) — CSS

방 둘이 엘리베이터 왼쪽 구역에 떨어져 있고, 계단 옆 가운데 구역에 금고실, 화장실 오른쪽은 방 없는 **본부 안내 라운지**다.

- **왼쪽 구역 (32..1790)**: **재무회계팀 사무실**(64..884, 놋쇠 칸막이가 있는 장부 칸 유리) → 화분(942) → **본부장실**(1000..1520, 대리석 벽과 금빛 명판) → 정수기(1600) · 화분(1720).
- **가운데 구역 (3086..3556)**: **금고실**(3104..3536, 리벳 강판 벽, 가운데 바퀴 달린 금고 문. 문이 다른 문보다 14px 높게 y=236에서 시작).
- **오른쪽 구역 (4282..4968)**: **본부 안내 데스크**(4460) → 대기 소파(4760) · 화분(4925).

### 재무회계팀 사무실 (`f10-finance`, 전면 820px → 내부 3444px, 비율 4.2)

- 화분(100) · 캐비닛 셋(210·290·370) → 책상(600) → **회계 책상**(880) → 책상(1160) → 복합기(1400) → 출구 → **결산 보드**(1960) → 책상(2360) → **재무팀장 책상**(2650) → 캐비닛(3150) · 정수기(3300) · 화분(3370).
- 출구: x≈1555.

### 본부장실 (`f10-director`, 520px → 2184px)

- 화분(100) → 출구 → **진열장**(520) → 캐비닛(660) → 소파(900) → 회의 테이블(1250) → **본부장 책상**(1700) → 화분(1960) · 캐비닛(2090).
- 출구: x≈256.

### 금고실 (`f10-vault`, 432px → 1814px, 창 없음)

- 캐비닛 셋(120·200·280) → 사물함(460) → **이중 잠금 서류함**(700) → 출구 → 진열장(1150) → 캐비닛 둘(1350·1430) → **금고실 UPS**(1650). 벽은 리벳 강판.
- 출구: x≈838 (복도 문과 같은 y=236 높이).

출구 위치는 `scene-builder.js`의 `exitDoorX`(문 양옆 벽 비율)로 계산한 값이다.

### 장치: 이중 잠금 서류함 (구현됨)

금고실 서류함은 열쇠 구멍이 둘이다(`requires: ['f10-key-finance', 'f10-key-director']`).

| 가진 열쇠 | 결과 |
| --- | --- |
| 없음 | `missingMessage`·`missingSheet`: "재무팀장·본부장 열쇠를 함께 돌려야 열림." |
| 하나 | `partialMessage`: "열쇠 하나를 꽂아 돌렸지만 걸쇠가 풀리지 않는다." |
| 둘 다 | 서랍이 열리고 전력 계약 변경 신청서(document)가 나온다 |

열쇠는 서로 다른 방에 있다: 재무팀장 책상(재무회계팀 사무실 2650, 다섯 책상 중 가장 안쪽)과 본부장 책상(본부장실 1700). 서류함은 금고실의 일반 캐비닛 사이에 끼어 있고, 지금은 같은 `filing-cabinet` 그림 위에 놋쇠 열쇠 구멍 두 개(CSS `.floor-prop.double-lock::after`, 소품 높이 20% 지점 가운데)만 얹혀 있다.

진행 순서: 엘리베이터로 10F 하차 → (선택) 복도 안내 데스크 → 금고실(서류함 라벨로 열쇠 둘이 필요하다는 것을 앎) → 재무회계팀 사무실(고지서·결산 보드, 재무팀장 책상 열쇠) → 본부장실(비용 검토, 본부장 책상 열쇠) → 금고실 서류함. 방은 순서와 상관없이 들어갈 수 있다.

### 실제 크기 확인 (1cm ≈ 0.926px, 수호 162px = 175cm)

`게임 높이 = 실제 높이 × 0.926`. 스크립트는 원본의 투명 여백을 **잘라낸 뒤** 불투명 그림을 캔버스 안쪽 (W−16)×(H−16)에 비율을 유지해 최대로 넣고, 게임은 캔버스 전체를 `worldWidth`에 맞춰 늘린다. 그래서 잘라낸 그림의 가로:세로를 r이라 하면:

- r ≤ (W−16)÷(H−16) (세로가 먼저 닿음): **게임 높이 = (H−16) × worldWidth ÷ W**. 그림 비율과 상관없이 이 캔버스·게임 너비에서 나올 수 있는 최대 높이다. 폭만 좁아진다.
- r > (W−16)÷(H−16) (가로가 먼저 닿음): **게임 높이 = (W−16) ÷ r × worldWidth ÷ W**. 그림이 넓을수록 낮아진다.

경계 r: 256×512는 0.484(240÷496), 512×256은 2.07(496÷240).

| 파일 | 목표 실제 높이 | 목표 게임 높이 | 최대 게임 높이 (경계 r) | 프롬프트 비율 r | 예상 게임 높이 | 지금 소품 높이 |
| --- | --- | --- | --- | --- | --- | --- |
| double-lock-file-cabinet | 135cm (내화 보안 캐비닛) | 125px | 139.5px · 151cm (r=0.484) | 약 1:1.85 (0.54) | 125.0px · **135cm** | filing-cabinet 약 151cm |
| executive-desk | 110cm (책상 76cm + 스탠드·명패) | 102px | 118.1px · 128cm (r=2.07) | 약 2.4:1 | 101.7px · **110cm** | office-desk 약 127cm |

"지금 소품 높이"는 게임용 PNG의 불투명 높이 × `worldWidth` ÷ 캔버스 폭으로 쟀다(filing-cabinet 496px, office-desk 239px).

계산 예: 이중 잠금 서류함은 r=0.54 > 0.484라 가로가 먼저 닿는다 → 240 ÷ 0.54 = 444.4 → 444.4 × 72 ÷ 256 = 125.0px → 135cm. 같은 캔버스·너비의 일반 캐비닛은 r≈0.405로 세로가 먼저 닿아 496 × 72 ÷ 256 = 139.5px → 151cm다. 본부장 책상은 r=2.4 > 2.07 → 496 ÷ 2.4 = 206.7 → 206.7 × 252 ÷ 512 = 101.7px → 110cm.

**주의**: 생성 후 잘라낸 불투명 영역의 비율 r이 위 표에서 **±10%를 넘으면 다시 만든다.** 둘 다 가로가 먼저 닿는 쪽이라 **넓게 나오면 낮아지고, 좁게 나오면 최대값까지 커진다.** 특히 이중 잠금 서류함이 r 0.484 아래로 좁게 나오면 151cm로 커져 옆 캐비닛과 실루엣이 같아지므로, **낮고 두툼한 비율**을 꼭 지킨다. 본부장 책상은 사원 책상(127cm, 모니터 포함)보다 낮게 잡았다. 모니터 대신 스탠드와 서류 더미가 있는 넓고 낮은 책상이라 "윗사람 책상"으로 읽힌다.

### 나중 그림 후보 (이번 표 밖)

- **열쇠 책상 상태 시트**: 소품은 `sprite`(가로 상태 시트) + `stateBy`로 물건을 챙겼는지에 따라 칸을 바꿀 수 있다(11·13·14·16층이 이미 씀, `puzzles.js`의 `refreshReady`). 엔진 수정 없이 `floor-10.js` 데이터만 고치면 된다. 본부장 책상을 1024×256 2칸 시트(칸 512×256: 서류 밑에 꼬리표 달린 열쇠 / 열쇠가 빠진 뒤, `stateBy: 'f10-key-director'`)로, 재무팀장 책상도 같은 방식(`stateBy: 'f10-key-finance'`)으로 만들 수 있다. 두 칸의 캔버스·바닥선을 같게 맞추고(`docs/INTERACTION-SPRITES.md` 공통 제작 규격), 두 번째 칸은 첫 칸을 편집해 같은 실루엣으로 만든다. 상태 시트는 `prepare-floor-kit.ps1` 대상이 아니다.
- **이중 잠금 서류함 열린 상태**: `stateBy`는 물건 하나만 본다. 서류함은 여는 순간 `gives`가 없어 지금 데이터로는 열린 칸을 고를 수 없다. 서류함에 `gives`(예: `f10-power-contract`)를 더하는 데이터 수정을 하면 2칸 시트(칸 256×512: 닫힘 / 맨 위 서랍이 열려 서류가 보임)를 쓸 수 있다.
- **전력 상태 칸**: `poweredSprite`(16층 음성 주문 키오스크)를 쓰면 옥상에서 10F를 골랐을 때 소품이 켜진 칸으로 바뀐다. 10층 단서 소품은 모두 서류·가구라 이번에는 쓰지 않는다. 금고실 문 잠금 표시등 같은 연출은 1장 기획 메모와 함께 정한다.
- **배경 그림**을 만든다면 복도 한 장과 본부장실 한 장. 지상층이므로 7층·16층처럼 **켜진 그림과 소등판(`-off.png`) 한 쌍**으로 만들고 `background-power.js`의 `switchableBackgrounds`에 등록해야 옥상 전력 선택에 따라 바뀐다. 배경이 생기면 소품에 `data-art` 밝기 필터(`brightness(.68)`)가 걸리므로 위 소품 밝기도 다시 본다.

## 연결 시 체크리스트 (코드 수정 단계에서)

1. `floor-10.js`에서 소품 2종의 `file`만 바꾼다(`size`는 지금과 같다). 이중 잠금 서류함의 `requires`·`missingMessage`·`missingSheet`·`partialMessage`, 본부장 책상의 `gives`·`takenMessage`는 그대로 둔다. 재무팀장 책상과 금고실의 일반 캐비닛은 `office-desk`·`filing-cabinet` 그대로 둔다.
2. 이중 잠금 서류함이 옆 일반 캐비닛(151cm)보다 낮고 두꺼워 보이는지, 금고실 캡처로 확인한다.
3. 이중 잠금 서류함의 `style: 'double-lock'`은 남기되, `index.html`의 `.floor-prop.double-lock::after`(놋쇠 열쇠 구멍 점 둘)를 지우거나 새 그림일 때 끄는 규칙을 둔다. 그림 속 열쇠 구멍과 CSS 점이 겹치지 않는지 본다.
4. `index.html`에 `#dynamic-scene[data-theme="finance"] .room-door:is(.brass, .lacquer, .vault-wheel, .metal)` 이미지 규칙을 추가한다(`border: 0; background-size: 100% 100%; image-rendering: pixelated`). 금고실 문 상자가 150×334(y=236)로 그대로인지, 다른 층 화장실 문이 바뀌지 않았는지 본다.
5. `floor-kit/manifest.json`에 새 소품 2개를 등록하고(`width`·`height`·`anchor`·`suggestedWorldWidth`), `prepare-floor-kit.ps1 -Files ...`로 게임용 그림을 만든 뒤 `tests/elevator.mjs`의 `heights`에 새 파일을 추가한다.
6. `npm test`를 실행하고, 10층 복도·세 방·화장실 문을 **두 상태로** 캡처한다: 정전(손전등 원 안) / 옥상에서 10F를 골라 전력을 넣은 상태(덮개 없음). 바닥선 570px 정렬과, 켜진 상태에서 꺼진 그림이 어색하지 않은지 본다.
7. 새 그림의 실제 도구·프롬프트·출력 크기·남은 결함을 `assets/objects/floor10/PROMPTS.md`(문)와 floor-kit 제작 기록(소품)에 남긴다.
