# ARCHI 문제 및 수정 현황

정리일: 2026-10-20, 갱신일: 2026-10-22. main `65630c4` 이후의 플레이 개선과 후속 수정 기록을 통합한다.

이 문서는 대화에서 보고된 문제와 두 차례의 직접 플레이 관찰을 통합한다. 이전 수정 요청과 검증 기록의 핵심 내용도 아래에 이관했다. **재현된 동작, 설계 개선 제안, 수정 완료, 과거 기록만 있는 항목을 구분**한다. 아래 우선순위는 개발 순서를 정하기 위한 제안이며 확정된 기획은 아니다.

### 2026-10-22. 새 게임·불러오기 로봇 상태와 검사 오류

- R-03이 엘리베이터 문을 닫는 중 새 게임을 시작하면 이전 탑승 상태가 남아, 목적지가 없는 차량이 존재하지 않는 0층으로 이동했다. 불러오기·새 게임에서 R-03의 임시 순찰/탑승 상태를 9층 초기 위치로 되돌린다. 저장된 차량의 위치·유효한 운행 목적지는 유지하고, 이전 세션의 호출 예약·문 열림 타이머·로봇 문 열기 대결은 초기화한다.
- R-01은 새 게임·장면 이동 때 첫 감지 전 `dock` 대기가 `patrol`로 바뀌었다. 장면 이동에서 대기를 보존하고 저장에도 상태를 기록한다. 최초 감지 후에는 기존처럼 순찰로 재개한다. 상태 필드가 없는 과거 저장은 기존의 순찰 재개 규칙을 유지한다.
- `package.json`의 `sharp`와 누락된 하위 의존성을 잠금 파일에 반영했다. Playwright 고정 버전은 유지한다.
- 저장 검사는 삭제된 3층 자동문을 기대하는 대신 과거 저장의 해당 타이머를 무시하는지 확인한다. 충전 검사는 플래시의 500ms 점등 지연을 기다린 뒤 배터리 소모를 확인한다.
- [로봇 저장 회귀 검사](../tests/robot-save-reset.mjs)는 새 게임·브라우저 재시작·과거 저장, 최초 감지 전후, R-03의 탑승 5단계×차량 3칸, 정전 후 전력 복구를 검사한다. 테스트용 상태를 준비한 자동 검사이며 처음부터 엔딩까지 연속 수동 플레이한 결과는 아니다.
- 검증: `npm ci` 성공, 스크립트 문법 92/92 통과. 로봇 저장·일반 저장·슬롯·충전·R-01 순찰/회귀·R-03 순회·호출 우선순위·승강기 전력·앱 탑승 제한·B2 엔딩/포획·스토리 정합성·장면 로딩·목표 진행의 브라우저 검사 15개를 통과했다. 전체 `npm test`와 실기기 모바일 검증은 실행하지 않았다.
- 후속 청소 카트 요청: 도구 3개를 모두 치우는 대신 메모를 가린 양동이만 치우면 메모가 나타나고 주울 수 있다. 분무기·세제통만 치우면 계속 가려져 있다. 메모가 드러나면 키보드 초점도 메모로 옮기며, 부분 정리 상태는 저장·불러오기에도 유지한다. `floor17-power-circuit`, `item-acquisition`, `inventory` 3개 검사와 스크립트 문법 92/92를 통과했다. 마우스·브라우저 터치·키보드를 검증했고 실기기 모바일은 미검증이다.

### F01. 약 복용 후 정신력 감소가 멈추던 문제

- 최초 사용자 보고: 정신 회복약을 먹은 뒤 정신력이 더 이상 깎이지 않는다.
- 수정: `a50f26b`, [PR #5](https://github.com/hwanghj09/ARCHI/pull/5), main 병합 `c9d59ff`.
- 후속 변경 `393c293`에서 **정신력 +50 회복, 게임 시간 60초 감소 면제**가 의도적으로 추가됐다. 따라서 현재 약 직후 수치가 유지되는 현상 자체를 과거 버그의 재발로 판단하면 안 된다.
- 직접 플레이에서 복용 직후 10→60%, 어두운 상태에서 일정 시간 유지, 효과 종료 후 58%로 감소를 확인했다. 효과를 알려주지 않던 P08도 이번에 설명·HUD·종료 안내를 보완했다.
- 관련: [설정](../js/core/config.js), [정신력](../js/player/sanity.js), [회복·USB 회귀 검사](../tests/sanity-usb.mjs).

### F02. 앱 설치 없이 17층에서 내려갈 수 있던 문제

- 원인: 기존 탑승 제한은 일부 목표 제목만 확인했고 `solar-app-installed`를 필수로 검사하지 않았다. 앱 설치 목표가 떠 있어도 UPS만 복구하면 탑승할 수 있었다.
- 수정: 17층의 세 엘리베이터 모두 설치 플래그를 직접 검사한다. 문이 열려 있거나 다운로드만 마쳤어도 탑승을 막고, 내 자리 컴퓨터에서 앱을 내려받아 USB로 전송하라고 안내한다.
- 설치 후의 1층 조명 조건은 유지한다. 앱 없이 다른 층에 있는 과거 저장은 17층으로 돌아와 설치할 수 있다. 다른 층까지 일괄 차단해 복귀 불능으로 만들지는 않는다.
- 수정 커밋 `02ac382`, [PR #6](https://github.com/hwanghj09/ARCHI/pull/6), main 병합 `65630c4`.
- 검증: 수정 전 회귀 테스트 실패, 수정 후 세 칸×열림/닫힘×미다운로드/다운로드만 완료 상태 차단, 키보드·화면 버튼 이벤트, 설치 후 1층 도착, 과거 저장의 17층 복귀 통과.
- 관련: [탑승 검사](../js/interaction/interaction.js), [앱 탑승 회귀 검사](../tests/elevator-app-gate.mjs).

### F03. 13층 USB와 2층 리허설의 연결

- 사용자 보고: 보안 자료실에서 USB를 얻고 수동 크랭크로 탈출하면 곧바로 2층 목표가 나와 동기가 부족하다.
- 기존 코드에도 USB 재생 단계는 있었으나, 소지 즉시 재생할 수 있는 텍스트 중심 연출이었다. 연결 동작을 추가하고 실제 2층 행사장 에셋으로 손상된 객석 녹화 화면을 구성했다.
- 현재 흐름: **USB 획득 → 전력 차단·수동 크랭크 탈출 → 17층 내 자리 컴퓨터 → 외부 저장 장치 → USB 연결 → 03:00 리허설 녹화 확인 → 2층 조사**. 수호의 목소리와 2층 서버실 NAS 원본·04:00 삭제 안내가 방문 이유를 만든다.
- 2층 목표는 재생 완료 플래그를 명시적으로 확인한다. 장치 없이 앱을 열거나 재생 중 창을 닫기·최소화·PC 전력 차단으로 관람 완료를 얻을 수 없다. 중단하면 다시 연결해 처음부터 재생한다.
- [자료실 탈출 검사](../tests/vault-puzzle.mjs), [USB 연결·재생·저장 검사](../tests/sanity-usb.mjs)로 해당 구간을 검증한다. 전체 엔딩까지의 재플레이와 실기기 모바일 검증은 별도다.
- Chromium 터치 환경 390×844·844×390에서 연결·자막·다시 재생을 확인했다. 가로 화면에서는 영상 높이를 줄여 자막이 창 아래로 잘리지 않게 했다. 다운로드·설치 대기 5초+8초는 유지한다.

### F04. 순찰 로봇이 플레이어 호출을 덮어쓰는 문제

- 재현: R-03의 탑승 대기 중 같은 칸을 1층에서 호출하면 로봇이 그대로 탑승하며 목적지를 임의 층으로 덮어썼다. 로봇이 이미 탄 칸도 1층 도착 후 ‘로봇 순찰 대상이 아닌 층’으로 처리해 바로 다시 출발할 수 있었다.
- 원인: 빈 칸 선택에서는 `playerCall`을 확인했지만, 이미 진행 중인 로봇의 호출·탑승·하차 단계에서는 확인하지 않았다. 같은 층에서 문만 여는 상호작용도 호출 예약이 없었다.
- 수정: 타기 전 로봇은 플레이어에게 칸을 양보한다. 이미 탄 로봇은 호출 층에 도착해 기존 6초 문 열림 시간을 보장하고, 같은 층의 문 열기부터 탑승 전까지도 예약을 유지한다. 타지 않으면 기존처럼 예약이 해제되어 로봇이 다시 이용할 수 있다.
- [호출 우선순위 회귀 검사](../tests/elevator-call-priority.mjs)는 수정 전 목적지가 1층에서 다른 층으로 바뀌며 실패했다. 수정 후 로봇 탑승 전·후 호출, 1층 도착 후 대기·실제 탑승, 같은 층 문 열기, 예약 만료를 검증한다.

### F05. 더미층 서브스토리 정리

기준은 [원래 기획](../기획.md)의 ‘낮 성능 은닉 → 야간 몰래 학습 → 사건 당일 외부 복제 → 실패 시 마지막 호스트 선택’이다. [2차 작업](../2차%20작업.md)의 ‘방마다 단서를 찾는 상호작용을 없앤다. 게임 진행상 혼동을 주지 않기 위해서다’와 [3차 작업](../3차%20작업.md)의 해당 미완료 항목도 함께 반영했다.

6층의 현재 구현은 외부 사람과 직접 통화하는 대사 대신 ARS 인증으로 바뀌어 있었으나, 원래 기획에 없는 전화 사건·인증 퍼즐 자체가 남아 있어 함께 제거했다. 단순히 벨만 끄고 단서를 남겨 두지 않는다.

최근 사용자 요청으로 확정된 13층 USB → 17층 리허설 사본 → 2층 원본 조사 흐름과 5·8층의 현재 필수 퍼즐은 유지한다. 기존 저장의 과거 플래그는 보존하되 제거한 이벤트를 재생하거나 출입 조건으로 사용하지 않는다.

검증 완료(2026-10-21): [스토리 정합성 검사](../tests/story-consistency.mjs)에서 더미층 15개 방 출입, 6층 지연 전화 부재, 이전 저장, 핵심 목표 전환을 확인했다. `story-puzzles`, `scene-assets`, `manual-control`, `manual-control-art`, `audio-gameplay`, `floor-power-devices`, `script-syntax` 검사도 통과했다. 전체 엔딩 수동 재플레이와 장시간 `elevator.mjs` 통합 검사는 실행하지 않았다.

## 플레이 문제별 처리 결과

재현·결과 설명은 수정 전 관찰이다. **이번 처리**가 현재 로컬 변경이다.

### P01. 일부러 붙잡히면 약 없이 정신력 50%를 얻는다

**이번 처리:** 환각 재시도에서 정신력 50% 지급을 제거했다. 같은 자리·소지품·진행은 유지하고 다음 돌진 대기만 초기화한다. 게임 오버 창에 회복되지 않는다는 점과 플래시 대응·불러오기를 안내한다. 3회 반복 재시도에서도 0%가 유지되는 회귀 검사 통과.

- 재현: 편의점을 건너뛰고 B1 CCTV를 먼저 조사 → 소등 연출 뒤 정신력 13→0% → 방어하지 않고 환각에게 포획 → ‘다시 정신 차리기’ 선택.
- 결과: 같은 관제실에서 정신력 50%로 재개됐다. 출입증·낡은 열쇠가 유지됐고 제어반도 다시 조사할 수 있었다.
- 영향: 위험을 회피하고 약을 찾는 것보다 일부러 잡히는 선택이 유리해질 수 있다. 복구 장치가 곧바로 버그라는 뜻은 아니며 실패 보상 정책을 정해야 한다.
- 제안: 재개 위치·회복량·체크포인트 복원을 함께 검토한다. 반복 포획의 누적 영향과 모든 진행 플래그 보존 여부는 미검증이다.
- 관련: [정신력의 releaseHallucinationCapture](../js/player/sanity.js).

### P02. 아직 방문하지 않은 12층·7층의 내가 CCTV에 나온다

**이번 처리:** 고정 CCTV 그림을 유지하면서 설명·캡션을 ‘지나온 곳과 가본 기억이 없는 곳이 섞인 기록/예측’으로 보정했다. 방문 이력과 무관하게 모두 지난 기록이라고 단정하지 않는다. 원본 그림을 바꾸거나 새 영상 분기를 추가하지 않았다.

- 재현: 약·개발팀 조사 전에 B1 관제실에서 모니터 벽을 켠다.
- 결과: 설명은 ‘수호가 지나온 층을 차례로 되감는다’인데 고정 영상에는 이번 실행에서 방문하지 않은 12층·7층의 수호도 있다. 화면 표시와 소품의 접근성 설명을 대조했다.
- 영향: 자유 탐색에서 이야기의 시간 순서와 플레이 이력이 어긋난다.
- 제안: 방문 이력에 맞는 화면만 표시하거나 미래·예측 영상이라는 설정을 대사로 명확히 한다.
- 관련: [B1 CCTV 소품](../js/floors/floor-b1.js), [CCTV 연출](../js/scene/cctv-event.js).

### P03. 단서 없이 관리실 암호를 풀면 목표가 뒤처진다

**이번 처리:** 관리실 잠금 해제 플래그도 목표 조건에 반영했다. 메모 없이 암호로 열어도 ‘회로 안내도 확인’으로 넘어간다.

- 재현: 게시판을 읽지 않고 옥상 암호 1997 입력, 청소 카트 메모를 얻지 않고 관리실 암호 1706 입력.
- 결과: 암호는 인정돼 관리실에 들어갔지만 목표는 ‘관리실 비밀번호 찾기 / 관리실은 잠겨 있다’였다. 내부 회로 안내를 읽는 동안에도 유지됐다.
- 범위: UPS 연결 후에는 다음 목표로 넘어갔다. 영구 진행 불능으로 확인된 문제는 아니다.
- 제안: 메모 획득뿐 아니라 문 잠금 해제·진입 상태도 목표 조건에 반영한다. 이미 아는 암호를 쓰는 행동은 유지할 수 있다.
- 관련: [현재 목표](../js/ui/objective.js), [암호 처리](../js/interaction/keypad.js).

### P04. 전원이 없는 문이 배경처럼 보인다

**이번 처리:** 전원이 없는 문·게이트·단말·키오스크도 힌트와 조사 안내를 표시한다. 실제 키패드·조작·해제는 여전히 차단한다. 컴퓨터는 조명과 별도 UPS 전원 조건을 따르며 필요한 비상 회선을 안내한다.

- 재현: 정전 중 관리자실 문 앞에서 E를 누른다. 힌트·테두리·응답이 없다. 17층 조명을 켜면 도어락 입력 대상으로 바뀐다.
- 영향: 나중에 열 수 있는 문을 장식으로 오해하고 지나치기 쉽다.
- 제안: 대상을 완전히 제외하는 대신 ‘도어락 전원 없음 · 17층 전력 필요’를 표시한다.
- 관련: [deviceUnpowered](../js/interaction/power.js), [조사 대상 선택](../js/interaction/interaction.js).

### P05. ‘컴퓨터를 조사’ 목표가 관리실 컴퓨터로 오해된다

**이번 처리:** 다운로드 목표에 ‘17층 사무실의 내 자리 컴퓨터·블로그’, 설치 목표에 ‘파일 전송·USB’를 명시했다.

- 재현: UPS 복구 뒤 ‘전력 앱 내려받기 / 컴퓨터를 조사해보자’를 보고 바로 옆 관리실 모니터를 조사한다.
- 결과: 회로 안내도가 다시 열린다. 앱을 설치할 수 있는 것은 최초 사무실의 내 자리 컴퓨터다.
- 제안: 목표에도 ‘17층 사무실의 내 자리 컴퓨터로 돌아가자’를 명시한다. 수정 전에는 F02의 탑승 거절 안내에만 위치가 명시되어 있었다.
- 관련: [목표](../js/ui/objective.js), [17층 관리실](../js/floors/floor-17.js).

### P06. 빈 단서 탭과 비활성화된 자동 기록이 혼동을 준다

**이번 처리:** 의도적으로 제거한 자동 단서 수집은 복원하지 않았다. 빈 단서 탭은 숨기고 직접 메모하는 규칙을 안내한다. 과거 저장에 단서가 있으면 해당 탭을 표시하고 저장·열람을 유지한다.

- 재현: 게시판에서 승인번호 1997을 읽은 뒤 휴대폰 메모의 단서 탭을 연다. ‘기록된 단서 없음’이다.
- 수정 전 코드 확인: `recordClue`와 `addClue`가 즉시 return했다. 직접 쓰는 개인 메모는 별도로 존재한다.
- 제안: 자동 기록을 다시 제공할 단서를 정하거나, 단서 탭을 정리하고 직접 메모해야 한다는 규칙을 안내한다.
- 관련: [단서 기록](../js/interaction/clues.js).

### P07. 휴대폰으로 읽을 때만 자원이 소모된다

**이번 처리:** 휴대폰 메모 화면에 시간이 계속 흐르고 켜 둔 플래시가 배터리를 사용한다는 안내를 추가했다. 휴대폰을 통한 추격 일시정지 악용을 만들지 않도록 기존 소모·추격 규칙은 유지했다.

- 재현: 어두운 복도에서 플래시를 켜고 휴대폰 단서 화면을 10초 연다. 배터리 59→49%, 정신력 43→41%. 이어 게시판 조사창을 10초 보면 수치가 유지된다.
- 주의: 배터리 감소는 휴대폰 화면 자체가 아니라 계속 켜진 플래시의 비용이다.
- 영향: 게임 내 메모 대신 일시정지 후 외부 메모를 쓰는 편이 유리하다.
- 제안: 읽기·쓰기의 일시정지 규칙을 통일하거나 시간과 자원이 계속 흐름을 표시한다.
- 관련: [게임 루프](../js/core/loop.js), [휴대폰](../js/interaction/phone.js), [정신력](../js/player/sanity.js).

### P08. 약의 효과량·60초 보호·종료 시점이 보이지 않는다

**이번 처리:** 16층 약 설명에 +50%p와 60초 보호를 명시하고, B2 약에도 보호 시간을 표시했다. HUD에 남은 게임 시간을 초 단위로 표시하며 효과 종료 시 대사를 보여 준다. 복용·종료 회귀 검사를 추가했다.

- 재현: 설명은 ‘먹으면 불안이 조금 가라앉을 것 같다’인데 실제 효과는 +50 회복과 게임 시간 60초 감소 면제다. HUD에는 효과·잔여 시간·종료 표시가 없다.
- 영향: 정상 보호 효과를 ‘정신력이 다시 고장 나서 안 깎인다’고 오해할 수 있다.
- 제안: 아이템 설명에 효과를 적고 HUD에 진정 효과와 잔여 시간을 표시한다.
- 관련: [설정](../js/core/config.js), [아이템 설명](../js/interaction/inventory.js), [정신력](../js/player/sanity.js).

### P09. 지도를 야간 투시 화면처럼 쓸 수 있다

**이번 처리:** 장면 DOM·밝은 배경·가구를 복제하는 지도를 제거했다. 출입구·컴퓨터·충전 위치와 현재 위치만 표시하고 이름을 붙인 약도로 바꿨다. 지도 중 이동·시간 진행은 안내와 함께 유지한다.

- 재현: 플래시를 끈 어두운 편의점에서 지도를 열고 이동한다.
- 결과: 조명과 관계없이 방 전체의 가구·문·상호작용 지점을 밝게 볼 수 있고 지도를 연 채로 걸을 수 있다. 플래시 배터리 없이 동선을 파악할 수 있다.
- 주의: 지도를 열면 정신력 소모도 없어진다는 뜻은 아니다. 작은 점과 툴팁 위주의 방 이름 표기도 처음 읽기 어렵다.
- 제안: 이름이 읽히는 약식 평면도, 방문한 구역 표시, 지도 중 이동 정책을 검토한다.
- 관련: [지도](../js/ui/map.js).

### P10. 이야기 진행 제한의 이유가 늦게 드러난다

**이번 처리:** 탑승 힌트에 앱 설치·1층 조명·안내판 조건을 미리 표시한다. 컴퓨터 시설 안내 앱을 읽었으면 동일한 지식으로 인정해 로비 안내판 재조사 의무를 면제한다. B2 버튼과 제어반은 제한 해제 위치·필요한 준비를 구체적으로 안내한다. B2 핵심 조사 조건은 유지한다.

- UPS와 조명은 별도라고 배웠지만 1층 조명 전에는 도착한 승강기에 타지 못한다. 힌트는 ‘탑승’이고 눌러야 이유를 알려준다.
- 추격 뒤 편의점이 16층인 것을 알아도 로비 안내판을 E로 조사하기 전에는 탑승이 막힌다. 다른 시설 안내에서 얻은 지식은 인정되지 않는다.
- 첫 1층 방문 전 B1 버튼은 ‘1층으로 가서 퇴근하자’며 거절한다. 이후 B1은 먼저 방문할 수 있다.
- B2 버튼은 초기에 ‘아무 반응도 없었다’다. B1 제어반에는 키가 꽂혀 있지만 7층 로그·13층 백업 장치·2층 영상·CCTV를 먼저 확인해야 돌릴 수 있다.
- 제안: 필요한 이야기 순서를 유지할지 결정하고, 유지한다면 버튼·힌트에서 사유와 다음 행동을 미리 알려준다. 물리적 전력 부족과 주인공의 지식 제한을 구별한다.
- 관련: [탑승](../js/interaction/interaction.js), [층 버튼](../js/elevator/cabin.js), [제어반 조건](../js/floors/floor-b1.js), [목표](../js/ui/objective.js).

### P11. 실제 점등보다 성공 대사가 먼저 나온다

**이번 처리:** 전선 복구 직후에는 ‘장치가 켜졌다. 배전반에서 17층을 고르자’라고 안내한다. 공급 층이 0개인 상태를 점등 성공으로 표현하지 않는다.

- 재현: 옥상 전선 연결 완료 직후 아직 ‘공급할 층 선택 (0/1)’인데 ‘불은 들어오는데… 엘리베이터는 그대로네’가 나온다.
- 제안: 장치 가동과 실제 층 점등을 구분해 대사를 재생한다. 먼저 ‘가동됐다. 17층에 보내자’가 자연스럽다.
- 관련: [전력 복구 연출](../js/scene/solar-restore-scene.js), [태양광 배선](../js/interaction/wire-puzzle.js).

### P12. 첫 위협 전에 설비 작업이 길게 누적된다

**이번 처리:** 사용자 요청에 따라 다운로드 5초, 전송·설치 8초로 합계 대기 13초를 유지한다. 기존 퍼즐과 사전 앱 설치의 이점도 유지한다. 목표 위치와 상호작용 안내는 P05·P10·P13에서 개선했다. 초반 퍼즐 단계 삭제나 새 위협 연출 추가는 하지 않았으며 전체 초반 호흡은 추가 플레이로 판단해야 한다.

- 주관적 관찰: 열쇠 → 옥상 암호·배선 → 17층 조명 → 청소 카트 메모 → 관리실 암호·안내도·UPS 배선 → 사무실 왕복 → 다운로드·USB·설치 → 1층 조명까지 이어진다.
- 제안: 일부 단계를 뒤로 나누거나 복구 중 작은 위협과 세계 변화를 배치한다. 퍼즐 자체의 오류나 진행 불능으로 분류하지 않는다.
- 긍정적 관찰: 정전 전 앱 선설치는 실제로 허용돼 이후 사무실 왕복을 줄일 수 있다. 설치해도 옥상 전력 활성화 전에는 원격 조작할 수 없다. 이런 사전 준비의 보상은 유지할 만하다.

### P13. 열쇠 획득의 추가 클릭이 잘 드러나지 않는다

**이번 처리:** 열쇠 그림 아래에 ‘낡은 열쇠 줍기 · Enter’를 표시하고 조사창을 열면 획득 버튼에 초점을 둔다. 마우스 외에도 Enter 한 번으로 획득할 수 있다.

- 재현: 소화전을 E로 조사한 뒤 E를 다시 누르면 열쇠를 줍지 않고 창을 닫는다. 실제 획득에는 열쇠 그림 클릭이 필요하다.
- 제안: ‘줍기’ 표시, 기본 선택, Enter 안내 중 하나로 입력 문법을 명확히 한다.
- 관련: [아이템 조사·획득](../js/interaction/inventory.js).
