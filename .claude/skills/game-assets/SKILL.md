# 게임 에셋 제작과 연결

사용자 요청을 게임에서 사용할 수 있는 시각 에셋으로 구체화한다. 기존 프로젝트에서는
승인된 아트와 실제 구현을 기준으로 작업하고, 새 프로젝트에서는 요청에 필요한 최소 규격을 정한다.
픽셀 아트, 손그림, 벡터, 페인팅, 3D 렌더 기반 2D 이미지에 적용할 수 있다.
웹·모바일·데스크톱이나 특정 엔진을 전제로 하지 않는다.
3D 메시·리깅·오디오 제작은 이 스킬의 범위 밖이다.

## 1. 요청 범위를 정한다

현재 요청에 필요한 절차만 실행한다.

| 요청 | 결과 |
| --- | --- |
| 프롬프트·규격 작성 | 제작 사양과 프롬프트. 생성 결과가 있다고 보고하지 않는다. |
| 새 이미지 제작 | 실제 이미지, 필요한 검수와 짧은 제작 기록 |
| 기존 이미지 수정 | 수정본, 보존해야 할 요소와 변경 범위 검수 |
| 제공 에셋 가공 | 분할·정렬·리사이즈·포맷 변환·아틀라스와 필요한 메타데이터 |
| 게임에 적용·연결 | 에셋 검수 후 임포트·표시·상태·입력 연결과 해당 동작 검증 |

- “이미지부터”, “나중에 연결”이면 현재 작업에서 게임 로직을 추가하지 않는다.
- 기존 에셋 적용 요청에는 필요한 가공을 수행한다. 재생성할 필요가 있는지 먼저 판단한다.
- 그림 속 버튼·문·표시등과 실제 입력·충돌·게임 상태를 구분한다.
- 명확한 요청은 바로 진행한다. 기존 자료로 알 수 있는 내용은 먼저 확인한다.
  필수 참조 이미지 누락, 서로 양립하지 않는 요구처럼 작업을 막는 사항만 질문한다.
  영향이 작은 미지정 사항은 합리적으로 정하고 결과에 가정을 밝힌다.
- 기존 작업과 원본을 보존한다. 교체가 요청된 파일은 범위 안에서 갱신하되,
  무관한 파일 삭제·구조 개편·커밋·게시를 제작 과정에 끼워 넣지 않는다.

## 2. 기준과 환경을 확인한다

- 프로젝트가 있으면 관련 지침과 변경 상태를 확인하고, 유사한 에셋 1~2개를 실제로 열어 본다.
  소스 이미지, 임포트 설정, 제작 기록과 현재 사용 경로를 필요한 범위에서 읽는다.
- 승인된 캐릭터와 화풍을 보존한다. 참조가 캐릭터 정체성, 스타일, 구도, 수정 대상 중
  무엇을 뜻하는지 구분한다. 새 프로젝트에 임의의 장르·화풍·캐릭터를 강제하지 않는다.
- 연결 요청이면 해당 에셋의 로더·임포터, 애니메이션, 렌더러, 상태와 입력 경로를 확인한다.
  엔진·언어·폴더 구조·실행 명령은 실제 프로젝트에서 찾는다.
- 문서의 과거 수치와 현재 파일이 다르면 현재 사용자 요구와 실제 구현을 대조한다.
  문서만 믿고 월드 크기, 프레임 수, 기능의 구현 여부를 단정하지 않는다.
- 현재 제공되는 생성·편집·이미지 검사·엔진 실행 도구와 지원 포맷을 확인한다.
  에이전트 이름만으로 도구가 없다고 판단하거나 존재하지 않는 기능을 호출하지 않는다.

## 3. 필요한 제작 사양을 정한다

다음 중 해당 에셋에 필요한 항목만 정한다. 단일 아이콘 요청에 전체 명세서를 요구하지 않는다.
고정 수치를 재사용하기보다 요청, 승인 에셋, 실제 소비 코드에서 값을 얻는다.

| 항목 | 확인할 내용 |
| --- | --- |
| 용도 | 에셋 종류, 표시 위치, 정적 이미지·애니메이션·상태 전환 여부 |
| 아트 방향 | 화풍, 팔레트, 재질, 명암, 비율, 유지할 디자인과 참조 역할 |
| 시점 | 측면·탑다운·등각·원근, 카메라 각도, 방향 수와 방향별 차이 |
| 크기 | 파일 해상도와 게임 표시 크기, 월드 단위, 확대·축소 정책 |
| 배치 | 개별 파일·균일 격자·패킹 아틀라스, 셀 크기, 여백·간격, 읽기 순서 |
| 동작 | 상태별 포즈, 프레임 수·시간, 반복·왕복·단발, 전환·중단 조건 |
| 정렬 | 원점·피벗·발 기준선·고정 회전축, 프레임별 오프셋과 자르기 정책 |
| 배경 | 불투명·실제 알파·반투명, 그림자와 발광의 분리 여부 |
| 연결 | 식별자·경로·메타데이터, 레이어·정렬 순서, 입력·충돌과의 관계 |
| 출력 | 대상 포맷, 엔진 임포트·필터링·압축 조건, 반복 타일·화면 비율 |
| 예산 | 대상 환경의 최대 텍스처 크기, 메모리·로딩 목표, 제작 시간·횟수·비용 제한 |

캔버스 크기, 불투명 영역, 충돌 영역은 서로 다르다. 정사각형 셀, 한 줄 시트,
특정 기본 방향, 고정 해상도나 모든 에셋의 투명 배경을 전제하지 않는다.
이미지 제작만 요청받았고 연결 규격도 없으면 최소한의 일관된 규격으로 제작하고 이를 기록한다.

### 여러 에셋을 같은 기준으로 제작할 때

- 여러 캐릭터·아이콘·타일을 만들면 공통 팔레트·외곽선·광원·시점·피벗·표시 비율을
  작은 스타일 기준으로 정한다. 기존 아트가 있으면 그것을 기준으로 삼는다.
- 대표 에셋 하나를 먼저 만들어 목표 크기에서 품질과 연결 규격을 확인한 뒤 확장한다.
  사용자 검토가 요청되지 않았다면 이 단계를 별도 승인 대기로 만들지 않는다.
- 상태와 방향의 조합을 목록으로 관리해 누락을 확인한다. 의도적 생략·반전 재사용도 명시한다.
  구성만 다른 에셋은 레이어 재조합·팔레트 변형 등으로 재사용할 수 있는지 확인한다.
- 프롬프트와 설정의 공통 부분을 유지하고 변경 변수만 분리한다.
  출력 간 디자인이 달라지면 먼저 대표 에셋과 비교해 원인을 해결한다.
- 생성 호출 수·시간·비용에 명시된 제한이 있으면 그 안에서 진행한다.
  정해진 제한이 없어도 같은 결함을 수정 없이 반복 생성하지 않는다.

## 4. 도구와 제작 방법을 선택한다

- 새 아트 제작과 그림의 의미·디자인 변경에는 현재 사용 가능한 적절한 생성·편집 도구를 쓴다.
  로컬 참조 이미지는 먼저 열어 보고 도구가 지원하는 방식으로 전달한다.
- 기존 에셋을 재사용하면 충분한지 확인한다. 정확히 같은 결과가 필요하면 승인 원본을 재사용한다.
  같은 프롬프트만으로 동일한 픽셀이나 벡터가 재현된다고 약속하지 않는다.
- 분할·복사·회전·패킹·타일 출력·수치 정렬·형식 변환은 적절한 로컬 도구로 처리할 수 있다.
  프로젝트의 기존 빌드·변환 도구가 있으면 먼저 활용한다.
- 절차적 도형이나 SVG가 요청한 결과에 적합하면 사용할 수 있다.
  임시 도형을 요청받은 완성 아트나 이미지 모델 출력으로 설명하지 않는다.
- 도구 제한으로 제작이 막히면 원인과 가능한 결과 범위를 알린다. 원치 않는 대체물을 완성본으로
  내놓거나 한도를 우회하지 않는다. 새 유료 서비스나 인증 설정이 필요하면 사용자의 기존 허용 범위를 확인한다.
- 생성 원본과 최종 사용본을 구분하고 프로젝트 관례에 따라 저장한다.
  저장 경로, 파일명, 운영체제별 실행 파일 위치를 이 스킬에서 고정하지 않는다.

## 5. 프롬프트를 구체적으로 작성한다

아래 템플릿에서 필요한 항목만 채운다. 대괄호는 실제 요청에 맞게 바꾸고 불필요한 줄은 지운다.
프롬프트의 요구를 도구가 보장하는 출력 규격으로 취급하지 않는다.

```text
Deliverable: [asset type, intended use, required output format].
Reference roles: [identity to preserve / style only / composition / image to edit].
Subject: [character, object, environment, interface, or effect].
Art direction: [style, proportions, palette, materials, lighting].
View and orientation: [camera angle, projection, facing directions].
Canvas and layout: [dimensions, cells or separate files, margins, reading order].
States or frames: [what appears in each state/frame, timing intent if relevant].
Keep consistent: [design, scale, camera, lighting, baseline, pivot, fixed parts].
Change only: [specific action, state difference, or bounded edit region].
Background and layers: [alpha or opaque, separate shadows/effects if needed].
Constraints: [cropping limits, seamless edges, safe areas, unwanted additions].
```

- 캐릭터: 얼굴·실루엣·의상 등 유지할 정체성과 새 자세를 구분한다.
  좌우 반전 시 무기·글자·비대칭 의상이 바뀌어도 되는지 확인한다.
- 애니메이션: 프레임마다 다른 동작과 접촉 지점을 적는다. 단순 복제 프레임으로 동작을 대신하지 않는다.
  정지 구간은 의도한 유지 시간으로 표현할 수 있다. 여러 방향이면 방향별 기준과 순서를 명시한다.
- 상태형 소품: 같은 물체의 어느 부분이 바뀌는지 적는다. 회전물은 고정부와 회전축을 구분한다.
- 배경: 시점·레이어·보행면·출입구와 상호작용 위치가 필요한 경우 좌표나 영역으로 지정한다.
  원근이나 입체 표현의 허용 범위는 해당 게임의 카메라를 따른다.
- 타일: 반복 축, 변형 종류, 타일 간 연결 규칙과 가장자리 연속성을 지정한다.
- UI: 아트와 실제 텍스트·입력 요소를 구분한다. 가변 텍스트·번역·상태는 가능하면
  게임의 UI 시스템에서 처리하고, 일러스트에 포함해야 하는 글자는 내용과 가독성을 검수한다.
- 시각 효과: 재생 순서·수명·반복 여부와 알파·가산 등 실제 합성 방식을 확인한다.

## 6. 생성물과 가공 결과를 검수한다

결과를 실제로 열어 시각 검사하고, 가능한 항목은 파일 정보나 도구로 측정한다.

1. **내용:** 요청한 대상·상태·시점·방향·화풍·정체성인지, 잘림·불필요한 요소가 없는지 본다.
2. **파일:** 실제 해상도·포맷·색상 모드·알파를 확인한다. 벡터면 뷰박스·외부 리소스·폰트 의존성도 확인한다.
   요청한 크기나 확장자만으로 규격을 충족했다고 판단하지 않는다.
3. **시트:** 셀 수와 순서, 여백·간격·실제 프레임 영역을 확인한다.
   균일 격자에서 바깥 여백이 좌우 `mx`, 상하 `my`, 셀 간격이 `gx`, `gy`라면
   `cellWidth = (imageWidth - 2*mx - (columns-1)*gx) / columns`,
   `cellHeight = (imageHeight - 2*my - (rows-1)*gy) / rows`를 사용한다.
   정수 크기와 실제 셀 내용이 일치해야 한다. 패킹 아틀라스는 메타데이터의 영역·회전·트림 정보를 따른다.
4. **투명도:** 밝고 어두운 바탕에서 빈 영역·반투명 가장자리·번짐을 확인한다.
   체크무늬가 그려진 배경이나 모서리 알파 값만으로 투명도를 판정하지 않는다.
5. **정렬과 재생:** 프레임을 같은 피벗에 겹치고 의도한 속도로 재생해 발·고정부의 흔들림,
   크기 변화, 반복 경계와 상태 전환을 본다. 의도한 움직임까지 강제로 고정하지 않는다.
6. **가공 품질:** 픽셀 아트는 의도한 픽셀 격자를 보존하고 일반적으로 nearest-neighbor를 쓴다.
   다른 스타일은 적합한 보간을 선택한다. 비율 변형, 알파 손실과 반복 압축을 피한다.
7. **실제 사용 조건:** 타일은 반복 배치해 이음새를 보고, 아틀라스는 실제 필터·축소 단계에서
   이웃 셀 색 번짐을 확인한다. 필요한 경우 패딩·가장자리 확장을 적용한다.
   UI는 목표 표시 크기·대비·화면 비율에서, 효과는 실제 배경·합성 방식에서 확인한다.

불일치는 수정하거나 구체적인 제한으로 기록한다. 도구의 “동일 위치” 지시나 성공 응답을
시각 검수의 대체물로 삼지 않는다. 사용 가능한 도구로 확인하지 못한 항목은 미검증으로 표시한다.

### 에셋 종류별로 추가 확인할 항목

| 종류 | 해당할 때 확인할 내용 |
| --- | --- |
| 이동·공격 애니메이션 | 접지 구간의 발 미끄러짐, 동작의 준비·접촉·회복, 이동 거리와 프레임 타이밍 |
| 방향별 캐릭터 | 방향 전환 시 크기·피벗·장비 일관성, 대각선 대응, 반전으로 생기는 비대칭 오류 |
| 장비·분리 레이어 | 몸체와 머리·무기·의상의 정렬, 앞뒤 순서, 호환되는 포즈와 방향 |
| 타일·오토타일 | 직선·안쪽/바깥쪽 모서리·끝·교차 연결, 반복 패턴, 시각 경계와 충돌 경계 |
| 배경·패럴랙스 | 레이어 분리, 카메라 이동 시 빈 틈, 반복 경계, 다른 화면 비율에서 노출되는 영역 |
| 버튼·패널 | 기본·포커스·눌림·비활성·선택 상태의 구별, 색만 바뀌는 상태에 보조 표현 |
| 늘어나는 UI | 9-slice 또는 동등한 테두리 보존 영역, 긴 번역문, 최소 크기와 안전 여백 |
| 파티클·효과 | 시작·소멸 프레임의 튐, 겹침과 오버드로, 배경별 가독성, 요청된 저효과 설정과의 일치 |

고정 프레임 시간만 강요하지 않는다. 홀드 프레임과 프레임별 시간을 보존하고,
공격 판정·발소리 등 이벤트가 이미 있다면 재생 순서·속도 변경에 따라 어긋나지 않는지 확인한다.
이벤트 기능 자체를 요청 없이 새로 만들지는 않는다.

### 임포트와 성능 예산

- 디스크 파일 용량, 디코드 후 메모리, GPU 텍스처 메모리는 다르다.
  비압축 RGBA8 한 장의 기본 레벨은 대략 `width * height * 4` 바이트다.
  실제 메모리는 밉맵·압축 포맷·정렬·복사본 등에 따라 달라지므로 예산 판단 시 조건을 기록한다.
- 최대 텍스처 크기·지원 포맷·압축은 대상 기기와 실제 임포트 결과에서 확인한다.
  모든 환경에 2의 거듭제곱 크기, 하나의 거대 아틀라스, 특정 포맷을 강제하지 않는다.
- 재질·필터·배치 조건과 함께 로드되는 범위에 맞춰 아틀라스를 나눈다.
  작은 에셋 하나를 위해 무관한 대형 시트 전체를 계속 로드하지 않게 한다.
- 필터·밉맵·압축은 표시 배율과 카메라에 맞춘다. 픽셀 아트는 정수 배율과 픽셀 정렬도
  확인하되, 확대 전용 UI와 축소되는 월드 텍스처에 같은 설정을 일괄 적용하지 않는다.
- 색상 공간과 알파 합성을 확인한다. sRGB 이미지와 선형 데이터 텍스처를 구분하고,
  노멀·마스크 등 수치 데이터에 일반 아트용 색 보정을 적용하지 않는다.
  straight/premultiplied alpha 불일치로 생기는 검거나 밝은 테두리도 확인한다.
- 성능 문제가 있거나 최적화가 요청되면 크기·메모리·로딩·드로 콜 등 관련 지표를 전후 비교한다.
  렌더러·재질·겹침을 측정하지 않고 파일 압축이나 아틀라스만으로 성능 향상을 단정하지 않는다.

## 7. 요청된 경우 게임에 연결한다

1. 기존 로더·리소스 등록·임포트 설정을 사용해 에셋을 추가하고 프로젝트의 경로·식별자 관례를 따른다.
   네이티브 에디터의 리소스 ID나 메타데이터가 있으면 기존 참조를 보존한다.
2. 프레임 영역·행·열·피벗·시간·방향·오프셋을 실제 출력에 맞춘다.
   트림된 프레임은 원래 캔버스와 피벗을 복원할 수 있는 정보를 유지한다.
3. 기존 상태에서 애니메이션과 물체별 표현을 선택한다. 단발 완료, 반복, 취소,
   일시정지·재개와 장면 재진입 중 해당하는 전환을 확인한다.
4. 시각 레이어와 충돌·입력 영역을 구분한다. 프레임 크기 변화가 충돌체나 클릭 영역을
   임의로 바꾸지 않게 한다. 충돌 변경이 요청되었거나 필요한 경우 근거에 맞춰 갱신한다.
5. 배경에 그려진 대상과 새 스프라이트가 중복되지 않는지, 정렬 순서·가림·그림자·
   필터·압축·픽셀 밀도가 기존 화면과 맞는지 확인한다.
6. UI에는 해당 엔진·플랫폼의 실제 입력 요소를 연결한다. 그림과 입력 영역에 동일한
   크기 변환·크롭·앵커를 적용하고 사용하는 포인터·터치·키보드·컨트롤러 입력을 확인한다.
   모달 UI라면 월드 입력과 포커스 복귀도 확인한다.
7. 생성물 추가 때문에 별도 게임 시스템이 생겼다고 간주하지 않는다.
   표시등 켜짐과 전력 공급, 열린 문 이미지와 통행 가능 상태는 각각 실제 상태에 연결한다.
8. 에디터 미리보기와 실제 배포 빌드에서 경로·파일명 대소문자·포맷 지원이 달라질 수 있다.
   에셋 교체 후 이전 캐시·패킹 결과가 남는지도 확인한다. 가능하면 관련 대상 빌드에서 로딩을 검증한다.

정렬은 프로젝트의 좌표계·원점·단위·회전을 따른다. 단순한 2D 축 정렬에서만
`target = offset + scale * source`를 사용한다. 예를 들어 아래쪽으로 y가 증가하고
균등 배율인 배경의 바닥선은 `offsetY = targetBaseline - scale * sourceBaseline`으로 맞춘다.
다른 좌표계나 회전이 있으면 실제 변환 행렬 또는 엔진의 좌표 변환 API를 사용한다.

## 8. 기존 배경을 국소 수정한다

- 수정 영역과 보존할 구조·경계·조명·보행면을 지정한다. 해당 영역을 편집하고 원본을 보존한다.
- 출력 크기가 달라지면 편집 영역과 원본 사이의 좌표 변환을 계산한다.
  변경된 크롭을 무조건 덮어쓰지 말고 경계 연속성과 주변 변경 여부를 확인한다.
- 게임이 읽는 파일을 추적한다. 원본 외에 파생 타일·아틀라스·변환본이 사용되면
  기존 생성 절차로 해당 출력도 갱신한다. 자동 생성 파일만 고쳐 다음 빌드에서 수정이 사라지지 않게 한다.
- 배경에서 대상 제거를 요청했다면 입력 영역만 제거하고 끝내지 않는다.
  반대로 장식만 수정하는 작업에 불필요한 게임 로직 변경을 추가하지 않는다.
- 그림 속 출입구·장치와 실제 접근·충돌·상호작용 위치가 맞는지 확인한다.

## 9. 변경 범위에 맞게 검증한다

- 이미지 단독: 파일·내용·투명도·배치·정렬·재생을 검수한다.
  게임 코드가 그대로라면 전체 게임 테스트를 의무적으로 실행하지 않는다.
- 연결 작업: 실제 장면에서 로딩부터 표시·상태 전환·입력 결과까지 확인한다.
  관련 기존 테스트나 엔진 검증 도구를 사용하고, 회귀 위험이 있는 동작에 필요한 검증을 추가한다.
- 모바일·고해상도·다중 화면 비율 등 요청된 사용 조건을 확인한다.
  공유 렌더러나 리소스 시스템을 바꿨다면 영향을 받는 대표 장면도 확인한다.
- 스크린샷과 재생 검수는 로딩·디코드·임포트 완료 후 수행한다.
  파일 생성이나 테스트 통과만으로 시각 품질을 확인했다고 주장하지 않는다.
- 결함은 구체적으로 분류해 수정한다. 크기·피벗·프레임 순서 문제는 가공·메타데이터에서,
  얼굴·포즈·재질 문제는 아트에서, 상태·입력 문제는 연결 코드에서 먼저 원인을 찾는다.
  문제가 없는 부분까지 재생성하지 않고 수정한 부분과 인접 경계를 다시 확인한다.
- 실행 환경·도구 제한 때문에 검증하지 못했으면 무엇이 남았는지 구체적으로 적는다.

## 10. 저장하고 전달한다

최종 파일을 프로젝트의 기존 위치 또는 사용자가 지정한 출력 위치에 저장한다.
프로젝트가 없으면 에셋과 필요한 메타데이터를 함께 전달할 수 있는 폴더를 만든다.
제작 기록은 기존 관례가 있으면 따르고, 없으면 가까운 Markdown 파일이나 전달 문서에
아래 중 재사용에 필요한 정보만 짧게 남긴다.

- 실제 도구·모델·버전과 생성 설정 중 확인 가능한 것, 참조 파일과 그 역할
- 실제 사용한 프롬프트·수정 지시 또는 결정적인 가공 절차
- 최종 경로·포맷·해상도, 프레임·상태·타일 순서와 시간, 피벗·여백·정렬 규칙
- 연결한 리소스·상태·장면, 실행한 검증, 남은 결함과 미검증 사항

외부에서 가져온 에셋·폰트·소스가 포함되면 알려진 출처와 사용 조건·표시 의무를
기존 라이선스 파일과 함께 보존한다. 확인하지 않은 상업 이용 가능 여부나 독점성을 보장하지 않는다.

### 필요한 경우 함께 전달할 메타데이터 예시

개별 파일을 바로 사용하는 작업에는 별도 형식을 강제하지 않는다. 시트나 프레임별 오프셋을
다른 도구로 넘겨야 하는데 기존 형식이 없을 때만 아래처럼 최소 정보를 제공한다.
이 예시는 범용 전달용이며 특정 엔진이 그대로 읽을 수 있다고 가정하지 않는다.

```json
{
  "schemaVersion": 1,
  "image": "example-sheet.png",
  "imageSizePx": [128, 64],
  "coordinateSystem": "top-left, x-right, y-down, pixels",
  "alphaMode": "straight",
  "frames": [
    {
      "id": "idle-0",
      "rectPx": [0, 0, 64, 64],
      "sourceSizePx": [64, 64],
      "trimOffsetPx": [0, 0],
      "pivotPx": [32, 56],
      "rotated": false
    },
    {
      "id": "idle-1",
      "rectPx": [64, 0, 64, 64],
      "sourceSizePx": [64, 64],
      "trimOffsetPx": [0, 0],
      "pivotPx": [32, 56],
      "rotated": false
    }
  ],
  "animations": {
    "idle": {
      "frames": ["idle-0", "idle-1"],
      "durationsMs": [180, 220],
      "loop": true
    }
  }
}
```

`rectPx`는 시트의 `[x, y, width, height]`, `sourceSizePx`는 트림 전 크기,
`trimOffsetPx`는 트림 전 캔버스에서 잘라낸 영역의 좌상단, `pivotPx`는 트림 전 캔버스 기준이다.
회전 패킹이 필요하면 회전 방향과 해제 방법도 소비 도구의 규약에 맞춰 정의한다.
출력 전에 사각형의 시트 경계, 프레임 식별자 중복·참조 누락, 프레임 수와 시간 개수의 일치,
양수 재생 시간을 확인한다. 예시의 크기·시간·알파 방식은 실제 출력에 맞게 바꾼다.

프롬프트와 시드만으로 재현성을 보장하지 않는다. 필요한 원본·가공 설정·메타데이터를 보존한다.
전달 시 실제 파일 링크나 미리보기를 제공하고, **제작 완료**, **게임 연결 완료**,
**실행 검증 완료** 중 실제로 달성한 범위를 명확히 알린다.
