# ARCHI

정수호 스프라이트를 사용하는 2D 횡스크롤 사이드뷰 웹게임 기본 틀.

`index.html`을 브라우저에서 열면 실행됩니다. 서버나 빌드 과정은 필요하지 않습니다.

게임은 17층 사무실의 켜진 컴퓨터 앞에서 시작합니다. E 또는 화면의 상호작용 버튼을 누르면 컴퓨터 바탕화면이 열립니다. 파일 폴더에는 조직 안내, 주간 현황, 회의록, 성능 검증, 야간 설비, 출입 안내, 자료 보안, 인수인계 등 사내 문서 8개가 있습니다. 제목·담당자·문서번호 검색과 분류 선택으로 자료를 찾고 본문을 열어 읽을 수 있습니다. 사원증은 PC에 표시하지 않으며 기존 이미지 에셋만 보관합니다. 문서 내용은 게임 기획에 기반한 가상 자료이며 `computer-documents.js`에서 편집합니다.

업무 메모를 입력해 저장할 수 있습니다. 메모는 현재 브라우저의 로컬 저장소에 보관되며, 저장 실패 시 입력 내용은 현재 게임 세션에 유지됩니다. 컴퓨터를 조작하는 동안 캐릭터는 움직이지 않습니다. Escape는 열린 창을 먼저 닫고, 바탕화면에서 다시 누르거나 작업 표시줄의 종료 버튼을 누르면 게임으로 돌아옵니다. 진입·종료 모두 검은색 페이드를 적용합니다. 왼쪽 출입문까지 이동해 E를 누르면 17층 복도로 나갑니다.

17층에서는 상단 조명 체크박스로 사무실과 복도의 조명을 함께 켜거나 끕니다. 조명을 끄면 플레이어 주변만 부드럽게 보이고 반경 210px 바깥은 검게 가려집니다. 시야는 이동·점프를 따라가며 안내 표시는 계속 보입니다. 다른 층과 옥상에는 영향을 주지 않으며, 17층으로 돌아오면 조명 상태가 유지됩니다.

사무실·옥상 왕복과 엘리베이터 탑승·하차는 모두 검은색 페이드로 전환합니다. 약 0.35초 동안 어두워진 뒤 완전히 검어진 시점에 화면을 바꾸고, 약 0.35초 동안 다시 밝아집니다. 전환 중에는 이동·클릭·키보드 입력을 막고 완료 후 포커스를 복구합니다.

- 이동: A / D 또는 좌우 방향키, 화면의 ←/→ 버튼
- 달리기: Shift를 누른 채 이동 (걷기 200px/s, 달리기 340px/s). Shift를 떼면 걷기로 돌아오며 점프 중에는 점프·낙하 스프라이트를 유지합니다.
- 점프: Space / W / 위 방향키, 화면의 ↑ 버튼
- 상호작용: 가까이 서서 E, 화면의 E 버튼 (엘리베이터 호출·탑승 / 문 열기·닫기 / 층 이동)
- 사무실 출입: 시작 지점에 가까운 유리문에서 E로 들어가고, 내부 유리문에서 E로 나옵니다. 내부 문은 복도에서 본 것처럼 유리벽 왼쪽에서 39% 지점에 있고, 켜진 컴퓨터 책상은 그 왼쪽에 있습니다. 입구와 출구는 각각 하나이며 퇴실하면 들어온 위치로 돌아옵니다. 기존 두 번째 문은 배경에서도 제거하고 고정 유리 파티션으로 바꿨습니다.
- 층 이동: 도착한 엘리베이터 앞에서 E를 누르면 1인칭 내부 화면이 열립니다. 마우스로 층을 선택하면 잠시 후 문이 닫히고 이동합니다. 문 닫기 버튼으로 바로 출발 준비를 하거나, 문 열기로 출발을 취소할 수 있습니다. 도착해 문이 완전히 열리면 나가기 버튼이나 Escape로 하차합니다.

17층 복도에서 중력, 바닥과 벽 충돌, 카메라 추적을 확인할 수 있습니다. 통로의 박스 장애물은 제거되어 점프 없이 이동할 수 있습니다.
점프는 착지한 상태에서만 가능합니다. 걷기는 256×256 스프라이트 6프레임이며, 한 주기당 이동 거리 184px(약 0.92초)을 유지합니다.
공중에서는 상승 중 점프 프레임, 하강 중 낙하 프레임을 사용합니다. 엘리베이터 3개와 비상계단 문은 가까이 서면 강조되며 E로 열고 닫습니다. 문을 조작하면 조사→상호작용 2프레임이 0.42초 동안 재생되며, 이동·점프·포커스 해제 시 종료됩니다.
엘리베이터 3대는 층을 바꿔도 각각의 위치와 문 상태를 유지합니다(처음엔 모두 1층 대기). 호출과 탑승 이동은 한 층당 1.2초이며 표시창에 상승·하강 방향과 현재 층이 표시됩니다. 지하 1층과 1층 사이에 0층은 없습니다. 이동 중 문 열기·층 재선택·하차는 막히며, 내부 비상벨은 소리를 냅니다. 모바일에서는 내부 화면을 가로로 스크롤할 수 있고 탑승 시 버튼 패널이 먼저 보입니다.

B2·B1·1~17층 총 19개 층을 엘리베이터로 연결했습니다. 옥상은 엘리베이터에서 제외하며, 17층 오른쪽 비상계단 앞에서 E를 누르면 올라갑니다. 옥상 왼쪽 계단문에서 E를 누르면 17층으로 돌아옵니다. 옥상은 2400px 폭이며 야경 배경, 돌아오는 계단문, 화면이 꺼진 태양광 임시 전력장치가 있습니다. 전력장치는 현재 배치만 되어 있고 전원 공급 기능과 충돌은 없습니다. 기존 17층 복도와 사무실은 유지합니다. 16층은 기획의 공통 층 구조(방 3개, 엘리베이터 3대, 계단)를 따르는 경영지원팀 층입니다. 엘리베이터 왼쪽에 경영지원팀 사무실·소회의실, 오른쪽에 탕비실과 복도 휴게 공간(화분·소파)이 있습니다. 각 방의 문 앞에서 E를 누르면 방 내부(사무실·소회의실 2400px, 탕비실 1890px)로 들어가고, 내부 왼쪽 문에서 E를 누르면 들어온 문 앞 복도로 돌아옵니다. 방 배경에 문이 왼쪽 끝에 그려져 있어 복도에서도 각 방 전면의 왼쪽 끝에 같은 크기(높이 210)의 문이 있습니다. 방 내부 소품은 `assets/objects/floor-kit/` 에셋을 충돌 없이 놓았고, 문서 캐비닛·책상·복합기(사무실), 화이트보드(소회의실), 음료 자판기(탕비실)는 E로 조사해 정전 상황과 B2 야간 전력 이상을 암시하는 단서를 확인할 수 있습니다. 비상계단은 정전으로 잠겨 있어 이동하지 않습니다. 15층은 16층과 배치가 다른 인사총무팀 층입니다. 목재 마감 복도의 엘리베이터 왼쪽에 창 없는 문서 보관실(철문)·인사팀 사무실(나무문), 오른쪽에 방문객 대기실(양문)과 자판기 코너가 있습니다. 방 크기도 서로 다릅니다: 인사팀 사무실 3000px, 방문객 대기실 1800px, 문서 보관실 2600px이며 복도 전면 폭도 같은 비율(780/900/540px)입니다. 문은 보관실이 전면 왼쪽 끝, 인사팀 사무실과 대기실이 오른쪽 끝에 있고 방 안 출구도 같은 쪽에 있습니다. 문서 보관실은 창이 없어 수호 주변만 보이며, 바닥의 상자 2개를 점프로 넘어가야 안쪽 캐비닛에 닿습니다. 책상·화이트보드(인사팀 사무실), 안내 데스크(방문객 대기실), 출입 기록 캐비닛(문서 보관실), 복도 자판기를 조사하면 야간 잔류 인원 명단과 정전 직전 SYSTEM이 수호의 사원증 권한을 바꾼 기록을 확인할 수 있습니다. 1층 경비 로봇 사건의 복선입니다. 12층은 ARCHI 개발팀 층으로, 차가운 청회색 연구소 마감입니다. 복도와 방 세 곳의 벽·문·표지판은 CSS가 아니라 `assets/background/floor12/`의 월드 1:1 배경 그림(복도 5000×720 등)이며, `scripts/render-floor12-art.mjs`로 다시 만들 수 있습니다(`GENERATED.md`). 엘리베이터 왼쪽에 넓은 ARCHI 개발실(전면 가운데 사원증 리더기 문), 비상계단과 화장실 사이 가운데 구역에 성능 평가실(자동문), 오른쪽에 개발자 휴게실(둥근 창 문)이 있습니다. 방 안 폭은 복도 전면 폭의 4배입니다: 개발실 3600px(전면 900px), 성능 평가실 1808px(452px), 휴게실 2560px(640px). 개발실은 전면 가운데 문으로 들어가 방 한가운데에 서게 됩니다. 성능 평가실 자동문은 전원이 없어 열리지 않고("전원 없음" 표시), E를 누르면 유리 너머로 야간 평가 출력물(03:12 · 정답률 87.4%)이 보입니다. 내부(장비 벤치·랙)는 이미 연결되어 있어 전력 시스템이 생기면 `locked`를 풀면 됩니다. 성능 평가 보드(주간 정답률 4.6→3.1%), 프린터(낮 측정분만 있는 일일 리포트), 복도 전시 진열장(참가상 · 정답률 4.8%)이 낮의 낮은 성능을, 휴게실 소파 메모(새벽 서버 사용률 91%)와 사물함 공지(01:00~05:00 12층 전력 자동 차단)가 밤의 이상을 보여주고, 팀장 책상 메모가 7층 AI 테스트·검증실의 원본 로그 백업을 가리킵니다. 복도의 빈 경비 로봇 충전독도 조사할 수 있습니다. 아직 전력 공급 기능이 없어 모든 문구는 전원이 꺼진 상태 기준입니다. 배치는 `player.js`의 `FLOOR12_LAYOUT`·`FLOOR15_LAYOUT`·`FLOOR16_LAYOUT`(복도)과 `FLOOR12_ROOMS`·`FLOOR15_ROOMS`·`FLOOR16_ROOMS`(방 내부)에서 조정합니다. 나머지 15개 층은 빈 공간으로 바닥·양쪽 벽·엘리베이터 3대·잠긴 비상계단·화장실·층 표지판만 있으며 소품, 장애물, NPC, 퍼즐은 없습니다. 옥상을 제외한 모든 층(B2~17)은 17층과 같은 건물 코어를 공유합니다: 폭 5000px, 엘리베이터 x=1818/2148/2444(y=220), 비상계단 x=2906(y=232), 화장실 전면 x=3556..4282·출입문 x=3612(y=210, 폭 145). 모든 층의 화장실은 17층과 같은 화장실 내부(1800px)로 들어갑니다. 층마다 다른 것은 빈 구역 x=32..1790, 3100..3540, 4300..4968에 놓는 방과 소품뿐이며, 값은 `player.js`의 `BUILDING_CORE` 한 곳에서 관리합니다. 17층 외 층에서는 비상계단이 정전으로 잠겨 있습니다.

17층은 비상계단 오른쪽으로 복도를 확장해 총 5000px 너비입니다. 화장실은 E로 출입할 수 있고, 소화전을 조사할 수 있습니다. 관리자실 문에는 **관리자 외 출입금지** 표지가 있으며 현재는 잠겨 있습니다. 관리자실 내부(1800px, 책상·배전반·문서 캐비닛·공구장)와 복도 복귀 경로는 이미 연결되어 있습니다. 추후 `player.js`의 `FLOOR17.rooms`에서 `f17-manager`의 `locked`를 해제하면 출입할 수 있습니다. 새 방들도 17층 조명 상태를 공유합니다. 확장부 배경과 화장실은 `assets/background/floor17/service-corridor.png`, `restroom.png`를 사용하며 제작·정렬 기준은 `SERVICE-EXTENSION.md`에 있습니다.

방 안팎 일치: 모든 방은 복도 쪽 벽면 한 구간(`x`, `width`)을 차지하고, 방 안 출구는 복도 문과 같은 크기·높이이며 문 왼쪽과 오른쪽 벽 길이의 비율이 복도에서 본 것과 같습니다(`player.js`의 `exitDoorX`). 그래서 복도에서 문 옆에 방이 보이면 방 안에서도 같은 쪽에 그만큼 공간이 있습니다. 예: 화장실(벽면 x=3556..4282) 안 출구 x=185, 관리자실(4282..4968) x=324. 배경에 문이 그려진 방은 `exitX`로 그 위치를 적고 복도 문을 거기에 맞추며, 같은 층의 방은 복도 전면 폭과 방 안 폭의 비율을 맞춥니다. 17층 사무실 내부는 원본 배경을 기둥 단위로 재배치한 `office-interior-aligned.png`를 씁니다(`OFFICE-PROMPT.md`). `tests/room-geometry.mjs`의 검사를 각 층 테스트가 사용합니다.

맵 길이, 바닥 높이, 이동 속도, 경계 배치는 `player.js`의 상수와 `terrain`에서 조정합니다.
17층 배경은 `assets/background/floor17/tiles/`의 256×256 PNG 39장으로 구성됩니다.
`player.js`에서 13열 × 3행으로 연결하며, 바닥선은 충돌 좌표와 같은 y=570입니다.
조립된 아틀라스, 생성 원본, 내보내기 규격과 프롬프트는 `assets/background/floor17/`에 있습니다.
문은 `assets/objects/floor17/`의 별도 PNG 시트를 사용합니다. 프레임은 256×512, 시트는 512×512(왼쪽 닫힘 / 오른쪽 열림)이며 기존 배경의 문 위치를 덮어 표시합니다.
화면 크기를 바꿔도 플레이어의 월드 좌표는 유지됩니다.

물리 엔진은 [Matter.js 0.20.0](https://github.com/liabru/matter-js/tree/0.20.0)입니다.
오프라인 실행을 위해 배포본을 `assets/vendor/`에 포함했으며 MIT 라이선스를 함께 보관합니다.

검증: `npm ci` 후 `npx playwright install chromium`, `npm test`.
